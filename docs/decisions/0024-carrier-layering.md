# 0024. 载体分层：盒管模型（Luau 管 + wasm 盒 + 核心内建件）

- Status: accepted（Consequences 议题地图回填行中「A9 能力政策声明对账 = 盒能力笼的安装面」的时机措辞已被「启用期」取代——对账时机统一 = 启用期，2026-10-09 定案于 [luau-abi](../design/luau-abi.md) §A9.1 D24；正式局部 supersede 随 Luau ABI 冻结 ADR 一并立。另：Consequences C4「ABI 版本化第一天设计归 A10」已兑现 = §A10.1 D27（2026-10-10）；`metis sdk` 包装 wasm32-wasip2 管线的回填行接口位 = §A10.2 D28.1 `sdk box *` 族登记）
- Date: 2026-10-05

## Context

**产品模型前提**（[ADR-0021](0021-extension-language-runtime.md) 已立）：Metis core = 插件管理与组合机器 + syscall 层 VM 基底，**不提供任何 agent 领域服务**；一切领域功能 = 插件。推论：插件语言的上限 = 生态实现能力的上限，Luau 薄编排之上的密集逻辑必须有去处。

**盒管模型**（2026-10-04 用户提出并收口的分层框架）：经典模式里"盒子"（native 能力模块）构建期固定、只有"管道"（组合）可换；Metis 的目标形态是让盒也可换——**管 = Luau**（薄编排、文本即插件、Creator 唯一通道、毫秒热更）；**盒 = wasm 组件**（人写、编译来、进程内、实例即弃热换）；**固定盒 = 核心内建件**（json/crypto 等，构建期进核心）。

**T2 进程插件撤销一等位**（用户判决）：原生语言整插件独立进程背离初衷——组合被编译进 native 不可换、Lua 失去意义；wasmCloud v2 自我推翻进程外 capability provider 的官方复盘为外部佐证（见 [wasm-research](../research/wasm-research.md) §4.2）。MCP stdio 的 spawn 监管机器保留（监管外部服务 ≠ 插件形态）。

**wasm 调研**（[wasm-research](../research/wasm-research.md)，commit `f048a5a`）：四条冻结约束（每插件独立实例 / 内存限额 / 指令级中断 / 卸载零残留）在 wasmtime 49 均有原生机制；实例即弃经济成立；盒的 IO 全走 host imports = 天然全量可拦截、可进 journal——进程插件"replay 不透明"的代价整条消失。

**双 spike 实测**（2026-10-04，mlua 0.12.2 vendored Luau 0.740 / wasmtime 49.0.2，R7 5800X / 16GiB / NixOS，全 release；逐项方法与原始记录见 [wasm-research 补遗 1](../research/wasm-research.md)）：官方口径全部兑现或偏保守；调研的"wasm ≈ Luau 5–20×"推断被实测推翻——标量逻辑 **36–125×**，仅 C 算子密集代码 6.8×。

**syscall 层设计目标**（用户定调）：广而抽象的领域中性能力、一律业务粒度接口，使 Luau 保持薄编排（几十行：声明 + 组合 + 少量状态机）。

## Decision

### 1. 分层定妆（五层）

| 层           | 角色                                 | 技术                             | 可换性                                         |
| ------------ | ------------------------------------ | -------------------------------- | ---------------------------------------------- |
| **管**       | 薄编排/组合（<数百 µs 任务）         | Luau（+TS 前端登记扩展位）       | 毫秒热更；Creator 唯一通道                     |
| **盒**       | 业务粒度重物（>数 ms 任务）          | wasm 组件                        | 实例即弃热换（µs–ms 级）；IO 全走 host imports |
| **固定盒**   | 高频细粒度通用件（ns–µs 调用粒度）   | 核心内建件                       | 构建期确定，随核心发版                         |
| **外部服务** | wasm 撞墙区（GPU/推理本体/巨型依赖） | 部署组成（sidecar/MCP/远端 API） | 各自部署节奏                                   |
| **例外通道** | wasm 也盖不住的物理需求              | T2 进程插件                      | 进程重启；**撤销一等位**，单独立项才做         |

### 2. 盒的形态：插件包内能力制品（无插件身份）

- **盒 = 插件包内的能力制品**：五层主体内插件身份一律 Luau（fiber、邮箱、服务注册、事件订阅只在 Luau 层；例外通道与下方登记扩展位不受此限）；wasm 是包内 `boxes/*.wasm` 制品，经核心桥被属主插件调用，与属主**同生共死**（同版本、同热更单元、同权限归属、同分发包）。
- **进口面裁剪**：盒的 import = syscall 能力子集（时钟/随机/fs-preopen/http 等，按 manifest 能力政策授予），**结构上不存在服务调用与事件进口**——插件间接线（组合）可证明地全部在 Luau 文本。这是与 T2 判决一致的**结构保证**，不是政策倡导。
- **排除的形态**：完全转向 wasm 不用 Lua（Creator 部署内无工具链可写 wasm，自我进化链断，出局）；共享实例公共 lib（与每插件独立实例的冻结约束冲突——"共享"只能共享文件，落地即退化为包内制品的分发版，由 marketplace 渠道覆盖）。
- **登记扩展位**：wasm 一等插件（fiber 身份、直接 provide/listen）在 marketplace 出现纯 Rust 整插件真实需求时，以**裁剪 ctx 进口面**形态引入（服务/事件进口按 manifest 声明授予、未声明调用运行时拒绝；完整 ctx 进口面形态永不）；大而通用、多插件共享的引擎件（如向量检索、文档解析）可升级为核心托管 wasm 能力（v1 不做，位置预留）。
- **毕业路径**（单向）：自用 wasm 盒 → marketplace 分发 → 广泛采用达成共识且过第 4 节四判据 → 毕业为核心内建件（随核心发版带入）；内建件不降级回盒（降级是 supersede 级事件）。

### 3. WASI 0.3（追最新）

- **目标 WASI 0.3（追最新）**：自建 WIT 的接口语义按 0.3 形态设计（async / `stream<T>` / `future<T>` 为一等原生语义，接口设计不留 0.2 时代的变通形态）；wasmtime host 侧 46+ 已默认开启（标准 2026-06-11 发布）。
- **spike 实测实况**：host 侧 wasmtime 49 已备，但 guest 工具链未跟上——Rust 无 `wasm32-wasip3` target（rustup 仅提供 wasip1/wasip2）。落地形态：guest 的 WASI 进口走 wasip2（0.2）组件，wasmtime 按 world 自动分流；`wasm32-wasip3` target 落地后迁移（登记为复审触发器）。

### 4. 内建件 vs wasm 盒的分工线（四判据）

| 判据     | 内建件（固定盒）                                                      | wasm 盒               |
| -------- | --------------------------------------------------------------------- | --------------------- |
| 调用粒度 | ns–µs，循环内高频                                                     | ms 起步，业务粒度单次 |
| 通用度   | 领域中性，几乎所有插件用                                              | 领域相关或可选        |
| 物理约束 | wasm 有硬伤者必须内建（crypto 缺 AES/SHA 指令直通，调研推断差 3–10×） | wasm 内无硬伤者       |
| 稳定度   | 接口极少变，随核心发版                                                | 随插件演进，可随意改  |

中间地带（数百 µs–数 ms）看频率：高频偏内建、低频偏盒。能力清单逐项画线归 **B1 接缝能力集议题**（syscall 原语清单讨论）。**默认插件原则**：随发行捆绑的开箱即用插件集 = 普通 Luau 插件捆绑进发行包（VSCode 内置扩展模式：同 ABI、可读、可换、可热更），**不编译进核心二进制**——保自我迭代链（agent 改得动文本）与核心领域中性红线；集合内容归插件层议题另行立项。

### 5. 盒的热更与状态

- **默认纯函数**：盒无生命周期义务，写导出函数即可。
- **盒内状态 = 可随时丢弃重建的缓存**：允许攒（索引、解析缓存等），不承诺存活（热更/限额/崩溃都会丢实例），丢了重建。
- **可选导出**（尽力而为的优化，非义务）：`init()`（实例出生后跑一次，重建缓存用）；`snapshot()`/`restore()`（热换状态交接，格式作者自家事，同包同版本无兼容负担）。**无 teardown**：实例即弃无人能保证它执行；盒的外部资源全为核心句柄，随实例回收。
- **持久状态唯一去处**：小的 Luau 持有；大的/结构化的经 Luau 用核心能力（sqlite/fs 等）。
- 在途调用的排空策略与 Luau 插件热更统一口径（细节归插件热更新设计）。

### 6. 信任模型：盒不可读，信任照立

五道防线：

1. **能力笼**：盒的 IO 全走核心；组件自描述，进口清单可机械抠出与 manifest 能力声明对账；第 2 节的裁剪使接线在物理上藏不进盒。
2. **行为透明**：每次跨界调用进 journal，可回放、可归因——代码不可读，行为藏不住。
3. **来源链**（marketplace 信任三件套）：确定性构建（钉版构建镜像，发布交源码坐标+commit+镜像摘要+产物哈希，**marketplace 发布时重建对账**，闭源降级打"未复现"标）+ 结构校验（语言无关准入大门：组件合规 / 进口对账 / 导出对 schema / 禁用特性 / ABI rev 指纹）+ 签名（cosign 式 keyless 为主，marketplace 过检加签背书）。
4. **分级信任**：自写自用零审批 / 第三方三件套+安装时能力清单醒目展示（手机权限式）/ 第一方随仓评审。
5. **纪律兜底**：最小授权 + 数据分区（不给带网络能力的盒喂机密）。

包格式与分发载体细节归 **marketplace 格式设计任务**。

### 7. ADR-0021 局部 supersede 与 T2 地位订立

- **wasm 行**（局部 supersede）：原判决——wasm 当**通用插件语言**在 Creator 语境下正面违背 E1（源语言 → wasm 必过编译工具链，部署内无工具链可用）——在其语境下不变；本 ADR 改写该行的**适用范围**：wasm 组件以盒层载体身份入局。盒层定位不依赖墙外能力（墙即设计，与遏制哲学同向），故与判决理由"限制多、上限低"不冲突。
- **子进程行**（非 supersede，地位订立）：原判决文本（IPC 性能与部署重量，不当扩展语言运行时）不变；该判决针对的是"子进程当扩展语言运行时"，而整插件进程（T2）的载体地位此前从未进入冻结 ADR 文本——本 ADR 在此订立：**T2 撤销一等位**，降级纯例外通道（见第 1 节）。

### 8. 实测标定（spike，2026-10-04）

| 项                | 实测值                                                                                                                          | 原口径对照                                      |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| 实例化（pooling） | **1.7 µs**（冷启 11.6 µs，模块大小几乎不影响）                                                                                  | µs 级 ✓                                         |
| 中断开销          | fuel 1.022× / epoch 1.000×（病态形态 1.78×）                                                                                    | 官方口径 epoch ~10%、fuel ≈ epoch 的 2×——偏保守 |
| 内存限额          | 拦截全生效，稳态**零开销**；容量账 VA=槽×(预留+guard)、RSS≤槽×max 实测吻合                                                      | 需容量规划 ✓                                    |
| host 跨界调用     | **4.3 ns**（导出入口必须缓存：get_export 26 ns）；拷入 ~15.6 GiB/s                                                              | 数十 ns ✓                                       |
| `.cwasm` 预编译   | 加载比从源码编译快 **183–199×**                                                                                                 | 编译移出关键路径 ✓                              |
| **wasm vs Luau**  | **标量逻辑 36–125×（数值核 62.5×、逐字节文本 40×）；C 算子密集代码 6.8×；Luau NCG 对内建函数密集代码零加速**（仅纯 FP 核 1.9×） | ~~5–20×~~（推断被推翻）                         |
| WASI 0.3 guest    | **BLOCKED：Rust 无 wasm32-wasip3 target**                                                                                       | 标准已发布，host 侧 ✓，guest 工具链未跟上       |

粒度规则随之标定：跨界总成本 µs 级 vs 盒内 ms 级任务省 36–125×——业务粒度进盒的净收益比调研预期**更大**。同时"重活不在 Luau 里逐字节/逐元素循环"（该形态差距 40–62.5×，NCG 救不回）写进 SDK 文档。

## Consequences

**风险登记与跟进**：

| #  | 风险                                                | 处置                                                                                            |
| -- | --------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| C1 | fuel 计量 CVE 史（2026 年三起绕过）                 | 跟进 wasmtime 月度列车（多版本线回补，单次成本低）；fuel 仅确定性场景启用；deny 闸门拦 advisory |
| C2 | shared-memory 特性与限额/池化不兼容                 | 配置禁用                                                                                        |
| C3 | WIT × wasmtime × wit-bindgen 版本对齐（错配诊断差） | WIT 包 SSOT 入库、版本随 ADR 演进；加载失败把 WIT 指纹打进错误消息                              |
| C4 | ABI 版本化                                          | 第一天设计，归 **A10 工具形态与 ABI 版本纪律议题**                                              |
| C5 | wasmtime 依赖体量（Cranelift 依赖树大）             | 正式进项目时走 adding-dependencies 流程；vendored 锁版本对齐 mlua 先例                          |
| C6 | WASI 0.3 guest 工具链未落地                         | 见第 3 节迁移路径；wasip3 target 落地 = 复审触发器                                              |
| C7 | 动态语言盒滥用                                      | 文档定位"兼容层非性能层"；默认引导静态语言梯队                                                  |

**复审触发器**：wasm 组件模型能力质变；wasi:gpu 落地；PolkaVM 类替代技术成熟；`wasm32-wasip3` target 落地（第 3 节迁移点）；marketplace 出现纯 Rust 整插件真实需求（第 2 节扩展位激活评估）。

**对议题地图的回填**：**A2 manifest 格式议题**（`runtime` 字段与盒声明、能力政策声明）；**A6 边界转换细则议题**（线编码参照 Shopify NaN-boxed；大 Value 零拷贝/Arc 表示）；**A7 schema DSL 议题**（WIT = 盒侧形式化，schema 先行绑定生成）；**A9 deps/能力门槛议题**（能力政策声明对账 = 盒能力笼的安装面）；**A10 工具形态议题**（ABI rev 机制选型；`metis sdk` 包装 wasm32-wasip2 管线 + wasm-tools 验收）；**B1 接缝能力集议题**（内建件清单逐项画线；crypto 内建双重印证；SSE 流式的 wasm 侧答案 = 0.3 async）；**journal/replay 设计**（host imports 全量可拦截 + wasmtime 确定性工具箱：fuel/wasi-virt/NaN 规范化）。
