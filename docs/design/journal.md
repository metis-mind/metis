## 0. 术语锚点

- **journal**：核心的 append-only 操作/审计日志——每租户一本（[instance-model](instance-model.md) D60）、逻辑单流（host 单点定序单写者）、JSONL 一行一条（格式纪律 = D76/D77 + J4 D90）。
- **飞行记录仪**：journal 的自用定位——崩溃/故障后的调查源，不是状态重建源（D75）。
- **锚点条目**：携带版本/配置锚信息的低频生命周期条目（`boot` / fiber 进 Active）；普通条目不背版本税，审计按 `seq` 向前找最近锚点（D76）。
- **族**：kind 表按族组织（生命周期 / 能力使用 / 错误现场 / 控制）。**v1 = 写死族骨架**（D84 范围重定）：能力使用族仅 `process_*` 两条存活；内部流量族 / 聚合摘要族 / 档位概念（`core.audit` 三档）随可配审计面撤销，预制方案留档扩展位。
- **同步写**：骨架条目低频——intercept 点就地构造 + 序列化 + append + fsync 一步完成，无通道无 writer 任务（D84 收缩自 D82/D83 管线设计；seq 由写入点单线程分配，文件序 = seq 序）。
- **段文件**：`journal/` 目录下按 seq 区间轮转的物理文件组（布局/轮转/总量封顶/归档——**已收官 = D90**，2026-10-13）。活跃段 = seq_start 最大者（唯一可写）；封闭段 = 已有更新段存在（只读不可变，可手工归档/删除）。
- **blob**：超阈值 payload 的内容寻址存储（D7.1 平移）——**v1 不立**（D84：骨架无大 payload 场景，process 输出截断注记原位）；设计留档扩展位「可配审计层」。

## J1 定位与条目模型

### J1.0 边界与前提

本题定 journal 的定位、条目公共字段、自由态 Int 标记形态与 kind 表总装。不归本题：档位默认值与写入路径管线（J2）；崩溃恢复与跨重启连续性细则（J3）；脱敏管线 / blob / 段文件 / 保留归档（J4）；查询接口与人读面（J5）；replay 扩展位登记与冻结批次（J6）。前提（既定不议）：D7.3 格式纪律；D60 每租户一本；D72 条目不押实例字段；D73 跨实例调用 = 内部流量；ADR-0023 干净重启语义。

### J1.1 D75 定位锤：journal = 核心的操作/审计日志

- **定位**：journal = 核心的 append-only 操作/审计日志。消费者三层：**① 核心自己** = 崩溃/故障诊断（飞行记录仪本义：调查，不重建）+ 自审计；**② 插件层** = journal 查询接口（平台能力，J5 设计）；**③ 部署者** = 能力使用审计与调试（ADR-0024 §6 防线 2「藏不住」的兑现面）。（2026-10-12 修订注：② 插件查询面**缓议** = D84 骨架化（J5 转扩展位）；③ 收窄 = 管理动作/错误现场/process 可见，逐调用能力审计不立；「审计档位变化不许弄坏插件功能」随档位面消解。）
- **三条「不是」**（边界写实）：不是 replay 事实源（replay 引擎不立 = 扩展位）；不是运行日志（tracing/debug 输出 = 人读诊断面，既有边界不动）；不是插件 transcript（会话轨迹 = 插件层经 fs/sql 自建——DSH session log 已验证的形态；查询接口给插件的是审计关联面，不是存储面——**审计档位变化不许弄坏插件功能**）。
- **崩溃恢复 = fresh-start**：复用 ADR-0023 同一路径（全量 unload + 全量 load），崩溃与干净重启的差别只在在飞工作丢失多少，恢复路径不分叉。在飞邮箱消息崩溃丢失 = 诚实（D11.4/D11.5 同族：at-most-once、拒绝重投——被杀 handler 可能已发出过回复）。插件跨重启连续性 = 插件自己的 fs/sql 持久化（seam 落盘原子写纪律兜底）；待审批状态 = 审批机器文件原子写，不靠 journal。
- **正本退位**：fresh-start 后 journal 不是 system of record（正本 = 部署文件 + 插件私有存储），是派生诊断物——段文件轮转/保留/删除 = 纯运维政策，无完整性枷锁（Akka「不删事件」戒律只对 event-sourcing 正本成立）。journal 数据生命周期细则——**已收官 = D91**（2026-10-13，[config-format](config-format.md) §C7.0 登记位兑现）。
- **随之消解**（登记落档，各一句理由）：
  - §A6.7 概念地基「重启 = 重放」「b 崩溃恢复 = 核心层立身之本」——推翻为 fresh-start + 诊断；
  - 调研开放问题 1（单双流）——replay 流不存在，「保留期分叉」论据随之消失，单流自明；
  - 调研开放问题 3（fork 前缀物理组织）/ 4（发散比对强度）——replay 不立，消解；
  - M8 host 侧快照——replay 检查点，随 replay 消解；
  - 私有状态族（fs/sql）无 replay 政策（核心不立 replay）；
  - `nondeterminism_read` 族与 D7.2 生成型秘密加密——不录制时间/随机读取，则无密可泄、加密议题消失；
  - D8.2 在飞预算数值钉版登记、D1.6 免录恢复顺序的「确认」、旧载体面的确定性比对政策——replay 语义需求，消解（调度纯函数性本身 = ABI 既定，不动）。
- **replay 扩展位**（延期非删除）：replay 的消费者（调试 / eval / 「新代码重跑旧史」验证自我修改 = Fowler bug-fix 重放）真实存在，但在插件/agent 层且非 v1 必需；机器必须长在 host 侧（边界注入点是 host 的，插件无法虚拟化另一个插件的边界）。重开触发器与形态——**已登记 = D92**（2026-10-13，J6 收官）。wasm 盒 IO 全走 host imports = 天然可录制（wasm-research §5.7），届时是红利。
- **淘汰**：replay 引擎进 v1（为无消费者的 host 级虚拟化预埋复杂度）；「只审计不管诊断」（崩溃后没有飞行记录仪，核心故障无从调查）。

### J1.2 D76 公共字段定稿

每条必备：

| 字段       | 类型           | 说明                                                                                            |
| ---------- | -------------- | ----------------------------------------------------------------------------------------------- |
| `seq`      | u64            | **每租户**单调序号（每租户一本 = D60 的必然推论；host 单点定序单写者）                          |
| `wall_ms`  | i64            | 墙钟毫秒（展示用，不参与逻辑；[ADR-0015](../decisions/0015-payload-value-model.md) 时间戳纪律） |
| `kind`     | string         | 条目类型，封闭枚举（D78 kind 表 = SSOT）                                                        |
| `fiber`    | object \| null | `{slot, generation, plugin}`；host/核心动作条目 = null                                          |
| `cause`    | u64 \| null    | 触发本条目的条目 seq（因果链；Temporal 反向 ID 引用的单序列简化版）                             |
| `payload`  | Value          | 条目体（脱敏后；落盘纪律 = D7.3 + D77）                                                         |
| `redacted` | array \| null  | 被脱敏的 payload 路径 + 策略版本（M6 平移；审计可见「哪里被擦过」；形状钉死 = D89，2026-10-13） |

- **代码版本 = 锚点条目携带制**：普通条目只带 fiber 身份；版本锚信息由低频生命周期条目携带——`boot` 条目带 host_version + 配置树 hash；`fiber_state_changed` 进 Active 带 plugin_revision + config hash（实例件另带声明 hash——与 [instance-model](instance-model.md) D65 挂载快照三样一一对应：声明拷贝 → 声明 hash、配置合成结果 → config hash、代码版本 → plugin_revision）。审计问「当时跑的什么代码」= 按 seq 向前查最近锚点条目。漂移写实：`on_config` live-apply（合并取最新、不重挂载 = [config-format](config-format.md) D42）后 fiber 锚点的 config hash 变陈旧——「当时跑的是什么配置」= 锚点 join 沿途 `config_committed`（机器齐备，查询侧一次串联）。
- **淘汰**：(b) per-entry `code_ref`（调研 M4 原形：冗余税压在最密的能力族条目上，信息量不变）；(c) 不记代码版本（「当时跑的是什么」失明，违藏不住）。M4 的 `preset_revision` 消解——任务 5 后核心无 preset 概念，实例件由声明 hash 接替。
- 无租户字段（每租户一本，物理分离天然解决）；无实例字段（D72 结案原位）。

### J1.3 D77 自由态 Int 标记形态 = 包裹对象（§A6.7 D7.3 登记位兑现）

- **规则**：已知 kind 的声明字段 = 按 kind 表 schema 感知还原（D7.3 既定读侧），不包裹；**schema 管不到的自由态 Int** 落 `{"$int": "<十进制>"}` 壳——类型信息零静默丢失。
- **淘汰**：(b) 裸字符串不区分（自由态 Int/String 同落 JSON string，查询接口（J5）返回错乱类型 = 插件侧 bug 温床，违严格制）；(c) 安全域内保 number、超界转字符串（同字段类型随数值幅度漂移，违严格制；D7.3 对 seq/wall_ms 的例外是 kind 已知的固定字段，不许推广）。

### J1.4 D78 kind 表总装 + 消解记录

**分族原则**：生命周期族 + 错误现场族 + 控制族 + `process_*` 两条 = **写死全录**（低频 + 「藏不住」两面：管理动作与异常永远可见；控制族 = 审计自保同族——`journal_gap`（背压丢弃事实）与 `redaction_applied`（脱敏发生事实）若可配关，等于审计失明可由被审计面自己拨档，与 `audit_policy_changed`「谁关了审计窗必须可查」同构）；能力使用族其余 + 内部流量族 = **可配档**（`core.audit` 三档；键面与默认档**已收官 = D79/D80**，2026-10-12）。聚合摘要族（`window_summary`）= summary 档的载体形态，其有无随各族档位与活动走，自身不在 `core.audit` 键面。本表定 kind 存在性与 payload 形状；本表即 payload schema 的 SSOT（D7.3/D77 的还原依据）。（2026-10-12 范围修订注：**可配档面整体撤销 = D84 v1 骨架化**；本表已按骨架重排，被撤 kind 移入表后撤销记录。）

**载体吸收**（2026-10-18，W4.2/W4.6 拍板兑现）：`fanout_cancelled`（handler 结束强制取消子协程）——fan-out 不再是宿主 ABI 原语，等的事重叠 = guest 异步设施原生（`join!`/`select!`），宿主无观测点；该 kind 不立、无替代条目。正式 supersede = [ADR-0035](../decisions/0035-journal-fanout-cancelled-supersede.md)。

**mount/unmount 进 journal 的取舍**（D72 留下的「人读面与 journal 边界」裁定）：进——mount = 激活新代码的元权限动作（[instance-model](instance-model.md) D63），审计面少它 = 防线 2 破窗；成本 = 低频两条。D72 人读面 host 日志不动（人读告警与机读审计两通道并存）。

## J2 审计政策、音量与写入路径

> （2026-10-12 范围修订注：**本章可配族面整体撤销 = D84 v1 骨架化**——D79 键面 / D80 默认档 / D81 聚合形态不立；D82 收缩存活 = 写失败降级续跑政策（背压/通道/`journal_gap` 背压场景随可配面消失）；D83 收缩存活 = 落盘即 fsync + drain 排干（低频下分级不必要）。本章全文保留 = 扩展位「可配审计层」的预制方案，重开时按此落地。）

### J2.0 边界与前提

本题定可配族键面与默认档（D79/D80）、聚合摘要形态（D81）、写入管线与背压（D82）、flush/fsync 政策（D83）。不归本题：崩溃窗口叙事与跨重启连续性（J3——D83 只供原料）；脱敏管线 / blob 阈值 / 单条目字节上限 / 段文件 / 保留归档 / 写入量实测（J4）；查询接口与人读面（J5）。前提（既定不议）：D75 三层消费者与正本退位；D78 分族与写死/可配分轴；D50 三档枚举与封闭集机制；[ADR-0023](../decisions/0023-core-restart-semantics.md) drain 路径。

### J2.1 D79 键面扩展 = 六键

- **`core.audit` 键面 = `{http, fs, sql, timer, stream, internal}`**：能力使用族五键 + 内部流量族一键 `internal` 统管（`message_enqueued`/`dispatch_completed`/`service_call`/`service_result` 同升同降）。封闭集校验与新族 additive = D33/D50 机制原位。
- **写死族无键**：生命周期 / 错误现场 / 控制 / `process_*` 不进键面——没有键就没有拨档面，审计自保（D78 同构论证）在配置层结构性成立。
- **淘汰**：内部流量拆键（`internal_msg`/`internal_service`）——开窗精度换键面膨胀与部署者心智税；「服务调用低频」的音量论据由「summary 档聚合后本就小」覆盖，无需单开键。

### J2.2 D80 默认档 = 六族全 summary；防线 2 与 D23.3 结案

- **分档轴 = 结构有界原则**：音量假设不押「典型负载」（核心 agent-agnostic，爬虫插件 / 轮询循环 / 逐文件处理可把任何族刷成高频），必须在任意负载下成立——**默认面成本 = O（窗口数）**——条目数与单条字节双有界（每窗口每族至多一条；聚合分键基数封顶 = D81，字节不押 J4 上限兜底）；**full 成本 = O（调用数）**（无界，开窗自负）。「按族分频率定档」被淘汰（http/timer/stream「低频」前提不成立）。
- **默认档：六族全 `summary`**；`off`/`full` 可配照旧（D50 三档机制不动）。
- **[ADR-0024](../decisions/0024-carrier-layering.md) §6 防线 2 张力结案**：默认面 = 写死族全录 + 六族聚合可见 = **默认不盲**；「每次跨界调用进 journal」精确化 = 聚合级全覆盖 + 逐条可配开（残留写实：fs/sql 的**靶面**（路径/语句）默认仍不见、开窗可见——基数与敏感面权衡见 D81；「可回放」半句随 replay 不立同死——措辞注记**已吸收 = [ADR-0029](../decisions/0029-journal.md) 批次 #6**（2026-10-13））。
- **D23.3 审计写实结案**：internal 默认 `summary` → 自由态事件**流向**（谁 emit 了什么名、几个监听、几个错）默认可见；payload **形状**分歧 = 开窗可查（`internal: full`）。强度收敛写实：无契约事件「藏不住」= 流向藏不住、形状开窗见；有契约事件不受影响（`contract_violation` 写死全录原位）。
- **淘汰**：(b) 维持 D50 缺省 `off`——防线 2 默认失明照旧、D23.3 默认死亡，张力不结案；(c) 六族默认 `full`——音量税压给所有部署者且结构无界；(d) 默认 `off` 纯调试定位——崩溃后诊断不可能预约开窗（飞行记录仪默认失明），审计腿塌缩为「起疑后可开」= 防线 2 措辞重写面更大。**备查变体**：summary 档给 `message_enqueued` 记 payload 形状指纹（键集 + 类型 hash）——每消息 canonical hash 的 CPU 税 + hash 不可读（见分歧不见形状，仍须开窗），v1 不值；登记扩展位候选。
- **纪律注记**：fs/sql 缺省 `off`→`summary` = 对冻结中 [ADR-0027](../decisions/0027-config-format.md)（§C8.1 缺省档格；living doc D50）的语义修订——实现未落地、无部署可破，按演进纪律归 J6 冻结批次正式 supersede——**已吸收 = [ADR-0029](../decisions/0029-journal.md) 批次 #4**（2026-10-13）；§A6.8 实现期清单「audit 开关默认值 = 实现期配置」一行作废（设计期定案取代）。

### J2.3 D81 聚合摘要形态

- **聚合窗 = dispatch 窗口**：一次消息处理（插件被动模型下插件代码只跑在 handler 派发或 setup 里，无第三种执行上下文）；每（fiber × 窗口）独立聚合，窗口关闭（派发完成）时写出。
- **`window_summary` 合一 kind**（kind 表 +1 封顶）：每窗口至多一条，payload 按族分节、零活动族不节；**只携带档位 = summary 且有活动的族**（full 族由逐条条目自负盈亏，off 族无节）。形状：

```json
{
    "seq": 1235,
    "wall_ms": 1760000000123,
    "kind": "window_summary",
    "fiber": { "slot": 7, "generation": 2, "plugin": "tools/fs-helper" },
    "cause": 1230,
    "payload": {
        "trigger": { "kind": "event", "name": "user/msg" },
        "fs": { "read": 12, "write": 1, "bytes": 40211 },
        "sql": { "call": 3, "rows": 128 },
        "service": { "foo.bar": { "call": 2, "err": 0 } }
    }
}
```

- **双锚分工**：`trigger` 内联描述（触发消息的 kind/name 直书）= **常态主锚**——summary/off 档下 `message_enqueued` 不逐条，触发消息无条目可指，锚必须自给；`cause` 指向 `message_enqueued` 条目 = internal=full 档的因果链红利（无则 null）。
- **分键纪律**：分键只给**低基数高信号**维度——http 按域名、service 按（服务，方法）（配对信息聚合级无损：「POST api.evil.com ×47 共 2.3MB」照样扎眼）；fs/sql **不立路径/语句键**（高基数 + 敏感面大——量级可见、靶面开窗，不对称是有意的）。**分键基数封顶**：每族节超顶折叠进 `other` 桶合计（顶值 = 实现期配置）——单条字节随之结构有界（爬虫单窗口万异域名也封顶），不依赖 J4 字节上限兜底。
- **内部流量族 summary 载体 = `dispatch_completed` 增强**：**每消息一条**（router 视角，非每监听器）——`{msg: {kind, name}, from, listeners, err, enqueued, ms}`（`from` = 发射方 fiber，host 源 = null——「谁 emit 了什么名」的「谁」有着）；监听器级错误细节由 `listener_error`（写死族）兜底，不重复记账；`message_enqueued` 在 summary 档不逐条写，扇出计数折进 `enqueued`；`full` 档 = 四 kind 全逐条（`message_enqueued` 带 payload = D78「降档时摘要化」的反面）。每消息一条 = 消息驱动系统的**音量地板**（再低丢因果链；在 O（窗口数）原则内）。
- **高频族整形 = 档位语义本身**：summary 聚合折叠高频调用；full 开窗撞高频由背压吸收（D82）。不立采样——审计要完备或诚实缺口，采样两边都不是。
- **淘汰**：按族分 kind（`fs_summary`/`sql_summary`/…）——kind 表 +5~6 膨胀税，换 jq 少打一个字段。

### J2.4 D82 写入管线与背压

- **管线**：intercept 点（ctx 能力调用 / router / 生命周期机）只构造条目 + try_send；**每租户一个 writer 任务 + 一条有界通道**（每租户一本 = D60 的管线推论：单租户洪峰不卡他租户 journal；盘仍共担）。序列化与 IO 全在 writer。**seq 由 writer 单点分配**——「host 单点定序单写者」的精确兑现：文件序 = seq 序，崩溃后无乱序对账。通道容量 = 实现期配置。
- **背压 = 丢弃制诚实降级**：通道满 → 丢**可配族**新条目 + 按族计数；writer 察觉丢弃后写 `journal_gap`（payload = 丢弃计数 + 族分布 + 时间窗——D78「seq 区间」措辞精确化：writer 定序下被丢条目从未有 seq，区间义消解）。**写死族不丢**：走保留容量；保留容量也顶满 = 系统性危机 → writer **阻塞**写死族而非丢弃（低频族阻塞代价小）。
- **为何不沿用 D10.2 纯回压**：D10.2 回压保护的是内存与活性（回压链终端 = 投递方超时收场）；journal 回压的终端 = 全局消息派发减速——审计面反掐运行面，爆炸半径倒挂。丢弃制的合法性 = 正本退位（D75）：journal 是派生诊断物，丢得起，只要丢得诚实。
- **写失败（磁盘满 / IO 错误）= 降级续跑**：host 日志响亮告警（D25.1 warn 节奏）+ 续跑；writer 恢复后补 `journal_gap`（payload 带 `cause: write_error`）。失明窗口由告警 + gap 条目两端夹住，「藏不住」不破。淘汰 fail-stop 租户：Akka「journal 失败即停」戒律的前提是 event-sourcing 正本——D75 已排除；日志盘故障 → 租户停运 = 爆炸半径倒挂。
- **淘汰**：丢最旧（崩溃前尾巴恰是飞行记录仪最值钱部分，丢最旧 = 自毁长城）；intercept 点同步写盘（每次能力调用陪一次磁盘 IO，运行面被审计面拖死）。

### J2.5 D83 flush/fsync 政策 = 分级 sync

飞行记录仪的结构性讽刺：崩溃前最后几条最值钱，也最容易死在缓冲区。政策：

- **写死族条目 = 落盘即 fsync**（写时连带冲刷缓冲区全部待写 = group commit 式合批）：写死族低频（D78 定性），NVMe 单次 fsync 约百微秒；换来**错误现场与崩溃前管理动作不丢**——恰是崩溃调查的核心素材。**风暴写实**：错误现场族频率由插件行为可控（如 `listener_error` 风暴）——fsync 粒度 = writer 批次非逐条（group commit 原义：单批含写死族即整批一 fsync），持续饱和的尽头 = D82 保留容量顶满阻塞——「审计节流运行」在此侧如实存在，且仅在系统性危机时触发。
- **可配族条目 = 周期 flush**（时间或字节阈值先到先冲；数值 = 实现期配置，预算数值纪律原位）。
- **优雅关闭**（SIGTERM → [ADR-0023](../decisions/0023-core-restart-semantics.md) drain 路径）：writer 作为 drain 参与者排干通道 + 最终 fsync 后才退出——干净重启零窗口（fiber §10 优雅关闭细则的 journal 侧义务，本 change 落注）。
- **崩溃窗口写实**（J3 叙事原料）：崩溃最多丢「一个周期窗内的可配族条目 + 通道滞留」；写死族不丢。
- **淘汰**：逐条 fsync（可配族全量 sync = 写放大自杀）；纯 OS 页缓存（崩溃窗口不设防，最需要时失明）。

## J3 范围重定与崩溃恢复

### J3.0 边界与前提

本题定 v1 范围收缩（D84）与崩溃恢复/跨重启连续性的全部剩余面（D85–D88）。前提（既定不议）：D75 fresh-start 与正本退位；ADR-0023 干净重启路径；D58 崩溃 = 进程级。D84 后不归本题的面：可配审计层（扩展位，D79–D83 留档）；插件面查询接口（J5 缓议转扩展位）。

### J3.1 D84 v1 范围收缩 = 写死族骨架

- **动因**（用户定调）：梳理 J3 时确认——崩溃恢复不需要 core 做任何事（fresh-start = 全量 load 重跑 setup，配置/声明全在文件里）；v1 阶段「逐调用能力审计」无紧迫消费者；骨架实现成本 ≈ 零（低频条目同步写即可）。
- **收缩面**：journal v1 = 写死族骨架（生命周期 + 错误现场 + 控制 + 能力使用族仅 `process_*` 两条）。**撤销不立**：能力使用族其余十条 + 内部流量族四条 + `window_summary` + `audit_policy_changed` + `core.audit` 键面与三档（D79/D80/D81 撤销；config-format §C8.1 D50 格的 supersede——**已吸收 = [ADR-0029](../decisions/0029-journal.md) 批次 #4**（2026-10-13）——`core:` 节容器与封闭集/additive 机制原位）。
- **写入模型塌缩**：骨架低频 → intercept 点同步构造 + 序列化 + append + **逐条 fsync** 一步完成；无通道、无 writer 任务、无背压（D82/D83 大部撤销；存活 = 写失败降级续跑政策 + drain 排干义务）。`journal_gap` 收窄 = 写失败恢复标记。错误风暴写实：同步 fsync 的节流落在写入路径上（肇事者首当其冲，同租户其他 fiber 的写同排队——骨架正常面低频可承受；实测刺痛再批量化，不预埋）。
- **防线 2 结案改写**（取代 D80 结案）：v1 默认面 = 管理动作（boot/挂载/配置提交）+ 错误现场 + process spawn 可见；**能力调用细节（读哪些文件、联系哪些域名）v1 不立记录面**。不一致写实：`curl` 外泄可见（process）、`ctx.http` 外泄不可见。ADR-0024 §6「每次跨界调用进 journal」措辞 supersede——**已吸收 = [ADR-0029](../decisions/0029-journal.md) 批次 #6**（2026-10-13）。
- **D23.3 审计写实死亡**：内部流量族不立 → 自由态事件流向/形状均无记录面；静态面存活（analyze #7 非正式共享词汇警告原位）。
- **扩展位登记**：**可配审计层** = D79–D83 全文即预制方案（六键 + 三档 + `window_summary` + 背压管线）；触发器 = 首个真实审计需求或安全事件。
- **淘汰**：C 全砍（mount/process 的「藏不住」记录一并死，ADR-0024 信任模型抽腿）；保留 http 域名记录单点（ad hoc 例外破族轴纯洁性，扩展位可回）。

### J3.2 D85 崩溃自证：`shutdown_clean` + `previous_run`

- 生命周期族 +1 kind = **`shutdown_clean`**（写死全录原位）：优雅关闭（[ADR-0023](../decisions/0023-core-restart-semantics.md) drain）末尾写入该租户最后一条 + 最终 fsync。
- `boot` 条目 payload + **`previous_run: clean | unclean | first_boot`**：判定三分——无段文件/目录为空 = `first_boot`；段文件尾行 = `shutdown_clean` = `clean`；其余 = `unclean`（含撕裂尾行，处置 = D88）。（2026-10-13 修订注：多段下「段文件尾行」精确化 = 最新段最后完整条目行 + 头行孤段 = unclean——见 D90 判定兼容注；判定三分本体不变。）unclean 时 host 日志 warn 一条（D25.1 节奏：当场一条，不周期重发）。
- 插件侧无 core 信号（J5 缓议 + `journal/` 是 fs 豁免区）：需要崩溃信号的插件自建心跳文件（fs private + 原子写）。
- **成本**：每次干净关闭一条；换来崩溃频率在 journal 内自证可查。**淘汰**：不立关闭条目（崩溃与干净关闭不可区分，元问题失明）；boot 不标记（查询侧每次回溯 tail）。

### J3.3 D86 在飞丢失写实 + 崩溃孤儿进程

**丢失清单**（崩溃 = 进程级、全租户同死同起 = D58 原位）：

- **邮箱未投递消息 + 在飞 handler**：丢失诚实（被杀 handler 可能已发出过回复/副作用——at-most-once、拒绝重投 = D75/D11.4/D11.5 同族）；
- **对外副作用不回滚**：崩溃时已发出的 http/已写文件不回滚（§A3.10「副作用出视野不可回滚」平移）；
- **journal 自身**：至多丢正在写的那一条（同步写 + 逐条 fsync = D84，窗口 ≈ 零；撕裂尾行 = D88）；
- **不丢**：部署文件（正本）；待审批提案（审批事务暂存文件原子写 = ADR-0008/D39）；插件已落盘私有状态（seam 原子写纪律）。

**孤儿漏洞写实**：「drain 杀进程组无孤儿」（§A3.10）只在优雅路径成立——崩溃时 drain 不运行，spawn 的子进程可能孤儿残留。v1 **不承诺崩溃时无孤儿**；缓解 = OS 级随父死机制（Linux `pdeathsig` / Windows Job Object）登记实现期清单。诚实优先于好看。

### J3.4 D87 插件持久化与实例复活结案（核心零新机制；2026-10-12 用户拍板）

- **插件跨重启状态 = 插件自建 fs/sql**（private scope 目录 + 原子写 + sqlite 内建三件套）——核心机制已够，不立任何状态托管。「日志持真相、定时器为易失投影」四件套模式指导 = Creator/SDK 文档议题（登记）。
- **实例复活写实**（补实例模型空档）：**实例不自动复活**——mount 声明 = 文件背书（D62 审批档住挂载方 `config.yml`），boot 全量 load 后挂载方插件 setup 重跑 = 重新 `ctx.mount`，天然幂等；D65 快照语义原位（复活的新挂载拿新快照）；运行时构造的自管档声明不复活（易失物，挂载方自行重建）。
- **agent 连续性结案**：进行中的对话 = session 类插件 transcript 自建（fs/sql）；核心不提供任何连续性信号。

### J3.5 D88 崩溃窗口叙事定稿 + 撕裂尾行政策

- **存在性界定**：已 fsync = 存在；正在写 = 不曾存在（journal 无半成品概念）。骨架同步写下崩溃窗口 ≈ 正在写的那一条（D84），无需 `journal_gap` 类标记。
- **撕裂尾行政策**：append 写一半崩溃 = 段文件尾可留不完整行 → 一切读取侧（审计工具 / 工具面 / 未来查询面）**静默丢弃不完整尾行**、视为隐式 gap——崩溃是常态不是腐败，不响亮报错；不搞双写/校验和自保（正本退位 = D75，诊断物承受得起尾行损失）。
- 调研开放问题 5 至此**全结**（flush 政策 = D84 收缩版同步写 + 逐条 fsync；写失败 = D82 存活版降级续跑；窗口叙事 = 本条）。

## J4 写入侧工程（缩小版）

### J4.0 边界与前提

本题定骨架写盘的最后三块工程面：骨架脱敏形态（D89）、段文件物理组织（D90）、journal 数据生命周期（D91）。前提（既定不议）：D84 写死族骨架与同步写模型；D75 正本退位；D76/D78 字段与 kind 表（`redacted` 与 `redaction_applied` 的形状细节归本题钉死）；§A2.5 秘密按身份注册精确匹配；D29 部署根布局（`journal/` = 豁免区、gitignore）；D56/D57 fleet 租户目录。**消解随本章落档**：blob（D84 已记——骨架无大 payload 场景）；单条目字节上限（各产源既有预算兜底：process 输出预算 = §A3.10「输出带预算，超出截断」、错误 data 快照预算 = §A5.4/§A6.2——最大条目天然有界，不再单立上限）；写入量实测（骨架音量平凡，无量可测）。

### J4.1 D89 骨架脱敏 = 注册秘密值精确匹配扫

- **扫面 = 一切条目 append 前统一过扫**（payload Value 树序列化前遍历全部字符串值）：不单列 per-kind 清单——骨架低频 + 注册集小，成本 ≈ 零；清单 = 维护面与漏网面。「骨架脱敏面 = process 参数/错误消息」（D78 原表述）的读本 = 秘密实际能渗的两个口子（argv/command 直书、错误消息内嵌值），统一扫结构覆盖之；config 面无密可泄（配置树只许写引用、写明文 = 校验响亮拒绝 = D46 防呆）。map 的键不扫（键 = 结构字段名，非值）。
- **匹配纪律**：注册集 = secrets load/reload 管线按身份注册的秘密值（§A2.5 既定兑现；每租户一份——秘密只进属主租户 VM，扫描集天然租户隔离）；**全值精确匹配、大小写敏感、无模式匹配**；串内子串替换（同一字符串多处命中全替换）；多秘密值互相包含时**长者先替**（防部分遮蔽）。
- **替换形态**：命中处替换为 `[redacted:<身份名>]`（身份名非秘密——`config.yml` 本就明文引用 `{ secret: "<名>" }`）；条目 `redacted` 字段形状钉死 = `[{path, policy}]`（path = 相对 payload 根的 jq 风路径，如 `argv[1]`；同路径多命中合并为一条）。
- **策略版本 = 注册集内容 hash**（身份+值对排序后 sha256 截断 12 hex）：同身份换值也变版——审计可见「哪代秘密在泄」（轮换前后泄漏条目的 policy 值不同）。
- **`redaction_applied` 发射 = 紧随肇事条目写一条**：payload = `{policy, hits}`（同条目多处命中合计 = D78「聚合条目，非每命中一条」的精确兑现），`cause` = 肇事条目 seq。淘汰内存计数 + reload/drain 冲刷（引入崩溃丢计数窗口，诚实面反而变差；骨架低频下紧随写成本可忽略）。窗口写实：紧随两条各有 fsync，两条之间崩溃 = 肇事条目 `redacted` 字段仍在、计数条目可缺——`redacted` = 耐用真相，计数条目 = 便利聚合。
- **短秘密护栏**：值长 < N（N = 实现期配置）不注册进扫描集 + host warn 一条（注册时点一条，D25.1 节奏同族）——否则短值会把无辜文本大面积擦除。代价明写：被护栏挡下的短秘密若真渗入条目 = **明文落盘**（host warn 已披露该身份不在保）。
- **v1 不立**：vcrpy 式字段级可配钩子（`filter_headers` / `before_record` 类可调用改写）——归扩展位「可配审计层」预制方案随之一议。

### J4.2 D90 段文件物理组织 = seq 主序命名 + 头行版本 + 尺寸轮转 + 总量封顶

（2026-10-13 用户要求明写：core 长期运行——文件序列必须按时间有序；单文件大小与目录总量均须有结构界。）

- **文件名**：`seg-<seq_start 零垫20位>-<创建时间 UTC yyyymmddTHHMMSSZ>.jsonl`（例：`seg-00000000000000000000-20261013T045512Z.jsonl`）。**排序键 = seq_start**：字典序 = seq 序 = 时间序——seq 单调（写入点单点分配 = D84）是排序权威，时钟回拨打不乱；时间戳纯展示位（归档按日期捞文件顺手），同一秒多次轮转由 seq 前缀区分。
- **格式版本住段文件头行**（D7.3「文件头/条目带格式版本字段」悬案钉死 = 文件头侧）：首行 = `{"v":1,"seq_start":N}`，与条目同写盘纪律（建段即写 + fsync）；条目体不背版本税（D76 字段表不动）。头行非条目（无 `kind`），一切读侧跳过。
- **轮转 = 尺寸阈值**：追加前检查，当前段尺寸 + 本条字节 > T 则先开新段（T = 实现期配置）；封闭段只读不可变。淘汰按条数轮转（条目大小不一，字节才对应磁盘现实）与按时间轮转（引入时钟语义，无收益）。
- **保留 = 核心内建总量封顶**：目录总字节 > B 时**删最旧封闭段**至 ≤ B；**活跃段永不删**；B/T 均实现期配置且 B ≫ T（最差瞬态 ≈ B+T——活跃段自身轮转前仍可涨到 T）。封顶删除动作 = host tracing 一条（**不进 journal**——删的是派生诊断物，正本退位 = D75；kind 表不动）。**B 账只认 `seg-*.jsonl`**——归档/压缩品须移出目录；原位残留（如 `.gz`）不计入 B 也不被封顶删（部署者自负）。**段缺失写实**：seq 区间缺段 = 运维面动作（核心封顶或部署者手工），读侧不假装完整也不报错（「崩溃是常态不是腐败」= D88 同族）。
- **手工面**：封闭段 = 不可变纯 JSONL，部署者可随时 `rm`/`rsync`/`gzip`（归档/压缩 = 纯外部动作，核心无感知；D75「纯运维政策」原位）。**唯一约束 = 活跃段不可动**：动了 → 次 boot 误判双向——唯一段被删/清空 = 无证据误判 `first_boot`（漏发 unclean warn）；有封闭段残留 = 残段尾非 `shutdown_clean` 误发 unclean warn——两向危害同级，写实接受。
- **D85 判定兼容注**：`previous_run` 判定精确化 = 看**最新段**——有完整条目 → 其最后完整条目行（头行跳过；撕裂尾行丢弃 = D88）；**头行孤段（零完整条目）= `unclean`**——建段后必紧随条目写（轮转 = 追加触发；drain 的 `shutdown_clean` 同纪律），干净路径永不留下头行孤段，孤段 = 建段即崩的写实，**不回退读上一段尾**（回退会把轮转途中的崩溃误判成上一段的 `clean`）；「无段文件/目录为空 = `first_boot`」原位。**seq 续接同此读**：boot 时 = 最新段最后完整条目 seq + 1（头行孤段 = 其 seq_start——该段本就为这条目而建，seq 未被消费；首个 boot = 0 起）。
- **淘汰**：纯 seq 命名（时间不可读——用户要求驳回）；时间戳主排序键（时钟回拨乱序）；核心不删纯外部运维（用户要求驳回——长期运行须总量结构界）。

### J4.3 D91 journal 数据生命周期（§C7.0 登记位兑现）

- **生**：首个 append 时建 `journal/` + 首段（`boot` 条目 = 每租户第一写；目录创建幂等）。
- **存**：轮转 / 总量封顶 / 手工归档 = D90。
- **灭**：随租户目录——fleet 减员 = 改目录 + 干净重启（D57），租户目录删除 = 部署者动作，核心无额外处置。
- **不相交清单**：插件卸载/purge 不触碰 journal（D48 粒度 = 插件目录，journal = 租户级，两轴不撞）；部署索引不收（D34 扫描面 = `plugins/`）；gitignore 既定（D29）；备份/留史 = 部署者归档面自选。

## J6 replay 结案与 v1 收口

### J6.0 边界与前提

本题收官任务 6 剩余面：replay 引擎扩展位正式结案（D92）、冻结登记（ADR-0029 + supersede 批次七条 + rationale 层残留统扫入批）。前提（既定不议）：D75–D91 全部；冻结 ADR 格式与批次惯例 = ADR-0026/0027/0028 先例。

### J6.1 D92 replay 引擎 = 扩展位正式结案 + 重开触发器

- **结案**：核心不立 replay 引擎（D75 方向注的正式结案）。replay 的消费者（调试 / eval / 「新代码重跑旧史」验证自我修改）真实存在，但在插件/agent 层且非 v1 必需；机器必须长 host 侧（边界注入点是 host 的，插件无法虚拟化另一个插件的边界）。
- **重开触发器**（任一成立即重议，走演进纪律）：
  1. **「新代码重跑旧史」首个真实需求**——自我修改审批的实证化：用历史输入验证新插件版本的行为差（Fowler bug-fix 重放场景）；
  2. **agent 层 eval/确定性重放需求**实锤到插件层机器不够（需 host 注入点虚拟化边界）；
  3. **崩溃后连续性损失被证实不可接受**（fresh-start 的代价从理论变痛点）。
- **重开时复活资产**（留档原位，不重建）：调研 §7 映射 replay 面（M2 边界录制 / M3 行为化发散判定 / M9 对外网关纪律）；kind 表扩族（D78 撤销记录的边界输入类 + `nondeterminism_read` 类；生成型秘密加密议题随之复活）；wasm 盒 IO 全走 host imports = 天然可录制（wasm-research §5.7）；wasmtime 确定性工具箱（fuel/wasi-virt/NaN 规范化，ADR-0024 Consequences 留档）。ABI 面演进走 WIT package version 既定通道（W10 章）。
- **J5 缓议转扩展位**（同批确认）：插件面 journal 查询接口不立；部署者消费 = jq/文本工具直读段文件（D90 布局为此优化：时间有序文件名 + 头行版本 + 纯 JSONL）。

### J6.2 冻结登记

- **冻结 = [ADR-0029](../decisions/0029-journal.md)**：冻结面 = D75–D92 全部 + 术语锚点 + kind 表骨架；J2 章以「扩展位预制方案」地位随冻结留档（撤销状态本身是冻结内容的一部分）。
