## 0. 术语锚点与既定地基

### 0.1 术语锚点（本文档新增；共享术语见 [luau-abi](luau-abi.md) §0 / [seam-capabilities](seam-capabilities.md) §0 / [config-format](config-format.md) §0.1）

- **租户（tenant）**：进程内托管的部署根实例——一份配置树连同其 `plugins/`、secrets、journal 的运行时。静态、文件背书；审批/审计边界按租户划分。
- **部署树（deployment tree）**：租户的配置树运行时实例化（对应种子稿轴 2 的「全局树」行）；静态、文件背书。
- **租户树（tenant tree）**：租户的 fiber 运行时树——host 根 fiber（托管进程的总根）的子树（ADR-0010）。与部署树是同一租户的两个侧面：部署树 = 配置侧实例化，租户树 = 运行时侧实例化。
- **子树声明（subtree declaration）**：描述「挂哪些插件 + 实例级配置值」的数据。住插件侧，不进 `metis.yml`。
- **子树实例（subtree instance）**：host 按声明实例化的隔离插件子树；挂载语义（快照、账本挂靠、隔离粒度）归 S3 定。
- **动态子树挂载（subtree mount）**：从声明到实例的核心机制（S3 正题）。
- **session / persona**：agent 领域概念、插件层实体，由子树机制搭建；不进核心词汇表。

### 0.2 既定地基（本文档只承接，不重审）

- 部署根布局与配置树 = [ADR-0027](../decisions/0027-config-format.md)（D29–D52；living = [config-format](config-format.md)）：部署根 = 配置树文件所在目录；配置树 = 纯装配单；配置值住插件目录 `config.yml`。
- 子 fiber = 父的 effect（[ADR-0010](../decisions/0010-fiber-core.md)）；Context parent 链预留（[ADR-0013](../decisions/0013-context-scope.md)）；inject 驱动加载排序（[ADR-0001](../decisions/0001-inject-runtime-checks.md)）。
- 判别两问（它变了别的会话该不该跟着变 / 拓扑静态设置还是会话动态偏好）= [session-model](session-model.md) §3 定论，存活：动态偏好永进运行时状态，不进任何 YAML（D53 推论：同样不进子树声明）。
- 机器（模型）写入约束 = [session-model](session-model.md) §3 定论（随 config-format D36 平移后的版本），存活：机器永远碰不到人类层（`metis.yml` 正本与 secrets store）；声明写入的审批通道归 S3。
- 结构性隔离论证与轻/重分离论证 = [session-model](session-model.md) §6 定论，存活：前者是子树实例「每插件独立 `lua_State`」的机制输入（S3）；后者的租户级含义（跨租户重资源共享）——**已兑现 = D59**（S2）。
- D7 编程式 spawn 禁令（[ADR-0017](../decisions/0017-programmatic-spawn-deferred.md)）：插件代码内 `ctx:spawn` 的门关闭；「host 按声明实例化 ≠ 插件 spawn」的汇合点归 S3 正式定。

## S1 正名与用例归位（2026-10-11 收官）

### S1.0 边界与前提

本题定：机制定位与命名、三个用户用例（project / persona / session）的归位层级、议题地图。不归本题：租户托管细则（S2）、声明形状与挂载机制（S3）、实例配置与隔离边界（S4）、v1 范围（S5）。前提：任务 4 已冻结（ADR-0027）；用户定调 = 核心只提供抽象机制，领域概念归插件层。

### S1.1 D53 机制定位与命名（2026-10-11 用户拍板）

- 核心提供且仅提供**两层实例机制**：**租户托管**（静态、文件背书，S2）与**动态子树挂载**（动态、声明背书，S3/S4）。session/persona/project 等领域词不进核心词汇表——session/persona 是插件层用子树机制搭建的概念，project 是部署层的租户。
- 子树声明是数据，住插件侧；不进 `metis.yml`——配置树保持纯装配单（D31/D33 不动）。
- 机制默认**不要求遮蔽语义**：isolate（同 key 服务按子树换实现）是 S4 的独立复审题（luau-abi §A2.3 D32 登记触发器，复审排入 S4）；默认 = 全局服务解析不变。
- **命名定案**：租户（tenant）/ 子树声明 / 子树实例 / 动态子树挂载（subtree mount）。任务 5 改名「实例模型」。
- **session 归位结案**：session = 插件层实体（luau-abi §A6.7「核心是否有 session 概念 = 任务 5 待决 #1」在此结案：核心无 session 概念，只有 fiber 子树与子树实例）；journal 条目是否押实例字段的形态复审归 S4（A6.7 注入保留）。

### S1.2 D54 project 用例 = 单进程多租户（2026-10-11 用户拍板）

- 学习/财务管理类「项目」差异的性质 = 整套装配、数据、secrets、journal 审计边界全不同 → 归位 = **租户**（部署层）。
- 托管形态 = **单进程多租户**：一个 server 进程托管多个部署根。用户拍板理由 = 管理统一，不维护多个服务（淘汰本议题初议的「多进程零新机制」推荐——多进程买到的隔离/崩溃边界免费，单进程内由 host 以故障域隔离与统一 status 面补回；跨项目协作走网络不变）。
- 每租户 = 独立配置树 / `plugins/` 树 / secrets / journal / 审批域；部署根布局（D29）原样适用于每租户。
- **淘汰**：① 多进程每项目一 server（见上）；② 单树多项目（一套配置管多项目 = 用户明确排除的混乱形态）。
- **术语注意**：此「项目/租户」与 config-format C5/D44 砍掉的 workspace（fs 绑定机制）无关，勿混。
- 机制细则——**已兑现 = S2**（2026-10-11，D56–D60）。

### S1.3 D55 persona 用例 = 插件层归位（2026-10-11 用户拍板）

- **两读法记录**：(a) **纯数据路由**——persona = 一份命名数据（提示词、工具子集、模型参数），注册表住 agent 插件的 `config.yml`（审批可见）或 `data/`（自管），工具差异 = 工具路由插件按 persona 名过滤，零核心机制；(b) **子树实例**——persona = 一份子树声明（真·不同插件组合 + 实例配置值），每次会话实例化一份。
- **判读**：(a) 覆盖常态（人设差异多为数据差异）；(b) 是重武器（组合差异时才用）。两者都不需要核心内置 persona 概念，机制设计不为 persona 弯腰。
- **机制需求下限**（冻结为 S3 输入要求）：子树声明须能表达「不同插件集 + 不同实例配置值」。
- persona 建模（注册表形状、选择界面、审批策略）= 插件层议题，不进本任务冻结面。

## S2 租户托管（2026-10-11 收官）

### S2.0 边界与前提

本题定**租户托管的机制细则**：租户来源、增删时机、隔离与故障域、跨租户政策、管理面与标识。不归本题：子树声明与挂载（S3）；实例配置与服务解析边界（S4）；v1 范围（S5）。前提：D54（project = 单进程多租户）；ADR-0023（进程级干净重启、无重启专有钩子）；部署根布局（D29）原样适用于每租户。

### S2.1 D56 租户来源 = `--config` 单租户 + `--fleet-dir` 舰队目录（2026-10-11 用户拍板）

- **`--config` = 单租户模式，现状零变化**（D29 原样）。
- **`--fleet-dir <dir>` = 多租户模式**：直接子目录中含 `metis.yml` 者 = 租户（一级扫描，不递归）；**租户名 = 子目录名**（扫描唯一性构造保证，重名不可能）。无 `metis.yml` 的子目录 = 静默忽略 + `sdk check` 提示级列出（D34 未装配件政策同族：目录里多个目录不是核心的管辖事项，写码期教具提示）。
- **两旗标互斥**：同给 = 响亮报错（二选一不含糊）。
- **淘汰**：① host 配置文件（新文件种类 + 新分层的税，fleet 目录「目录即列表」零仪式平替）；② `--config` 可重复（租户集持久化推给启动行、basename 重名自管、顺序语义含糊——fleet 目录全解）；③ 递归扫描（隐式魔法）。
- **联动**：config-format §C1.1 D29 修订注（本 change 已同步）；本任务冻结时 ADR 批次吸收。

### S2.2 D57 租户集 = boot-only（2026-10-11 用户拍板）

- **增删租户 = 改 fleet 目录 + 进程干净重启**（ADR-0023 路径原样：全量 unload → 全量 load，无重启专有钩子；租户树生命周期复用同一条 drain/load 筋）。
- **代价明写**：重启中断全部租户的运行中会话（进程死则 VM 全灭，ADR-0023 Consequences；跨重启连续性 = fiber §10 登记 + 任务 6）。缓解：重启秒级；会话本质是短命子树实例（S3），其连续性归插件层持久化（此缓解以 S3 生命周期语义成立为前提；若 S3 反案则缓解弱化，运行时控制通道扩展位权重上升）。
- **淘汰**：v1 立运行时增删（需要 host 控制通道 = IPC/admin endpoint + 协议 + 鉴权一整套新机器）。
- **扩展位**：运行时租户控制通道；触发器 = 真实的「不中断增删」需求。

### S2.3 D58 隔离与故障域（2026-10-11 用户拍板）

- **租户 = host 根 fiber 下的独立租户树**（术语 §0.1；子 fiber = 父的 effect，ADR-0010 原样）。**每租户独立实例**：服务注册表、事件总线、部署索引、journal、secrets。
- **故障域 = 租户树**：单租户启用/运行失败 = 该租户 Failed + host warn 指路，不拖垮舰队。
- **D39 多租户细化**：fleet 模式下单租户配置（`metis.yml`/`overlay.yml`/`secrets.yml`）解析失败 = 该租户 Failed、其余照常 boot；**单租户模式维持「响亮拒启动」原样**（config-format §C3.2 / §C6.2 D47 修订注本 change 已同步；本任务 ADR 批次吸收）。
- **预算**：fiber 预算机制树粒度原样（租户 = 天然预算根）；跨租户配额/公平性 = 不立（扩展位，触发器 = 真实多租户争用需求）。
- **诚实边界**：核心代码 panic = 进程级，多租户不隔离此类失败。

### S2.4 D59 跨租户政策 = 默认零共享（2026-10-11 用户拍板）

- **无跨租户 inject / 事件 / fs**。跨项目协作 = 网络（HTTP 客户端插件调另一租户的插件 endpoint）——与多进程方案同一通道，不多买机器。
- **重资源**（llm 连接池等）= 每租户自实例，复制代价明记——种子稿「轻/重分离」论证的租户级落地：实例开销不是事，重资源复制才是；真痛了 → 共享服务独立部署（一个「基础设施租户」/独立进程）被网络调用。
- **扩展位**：跨租户共享插件实例；触发器 = 真实需求。

### S2.5 D60 管理面与标识（2026-10-11 用户拍板）

- **v1 三件套**：① host 日志面——租户状态变迁（Loading → Running / Failed + 原因指路）进 host tracing；Failed = 需人为动作的态，warn 政策同 D25.1 精神（状态变迁当场一条 + 每 boot 一次）；② `sdk check` 静态校验 fleet 目录（登记 sdk 工具面）；③ 端口/endpoint 每租户自管——插件 `config.yml` 各配各的，核心零路由机器（多租户不引入路由层）。
- **运行时 status 查询通道**（admin endpoint / IPC）= 扩展位，触发器 = 总览/前端需求真实出现。
- **journal = 每租户一本**（D54 推论落地）：段文件在各租户部署根 `journal/`（D29 布局零改动）；条目本体无需租户字段（物理分离天然解决）。luau-abi §A6.7「journal 属主 = host 进程一本」修订注 = host 托管 N 本、每租户一本（本 change 已同步）；任务 6 输入清单补条 = §A6.8 任务 6 行（本 change 已同步）。

## S3 声明与挂载（2026-10-11 收官）

### S3.0 边界与前提

本题定**从声明到实例的机制**：声明形状与素材约束、住处与审批关系、mount API 与能力门、生命周期、快照语义、D7 汇合结案。不归本题：实例配置 overlay 的合成与校验细则（S4）、子树内服务解析边界与 isolate 复审（S4）、实例标识与 journal 字段（S4）。前提：D53（机制定位）、D55（需求下限 = 声明须能表达「不同插件集 + 实例配置值」）；ADR-0017（D7 spawn 禁令与汇合登记）；ADR-0010（子 fiber = 父的 effect）。

### S3.1 D61 声明形状与素材约束（2026-10-11 用户拍板）

- **声明 = Value 数据**（mount 的输入；YAML 等价形示意）：

```yaml
plugins: # list 形——允许同 key 多实例（各带不同 overlay）
  - use: memory # 装配单 key 引用
    config: { ... } # 实例配置 overlay（可选；合成与校验细则归 S4）
  - use: blog-writer
```

- **素材约束**：`use` ⊆ **本租户**装配单（**enabled ∪ 休眠件**）。引用未装配件 = 挂载时响亮报错（D34 同族，「目录存在但树无 entry」指路面复用）；引用查无（目录都不存在）= 同族响亮、与未装配措辞两分（D34 既定区分原样）。**休眠件新角色 = 只供子树挂载的插件**——审批面完整保持：一切可运行代码都在装配单可见（休眠件的 capabilities 同进审批 diff）。
- **淘汰**：① 自包含声明（自带插件定义——违反目录单形态 D35，代码住处唯一 = 插件目录）；② 引用任意部署索引目录（审批后门：未装配件的 capabilities 从未进过审批面）。
- 实例化顺序 = inject 图驱动（ADR-0001 复用）；list 书写序只是书写序。
- 机制需求下限（D55）验收：声明能表达「不同插件集 + 不同实例配置值」✅。

### S3.2 D62 声明住处 = D36 两档分工平移（2026-10-11 用户拍板）

- **核心只定义声明形状（mount 输入格式）；住处 = 插件层议题**——不立任何新文件种类/新格式，与 D36「配置值住处 = 插件目录 `config.yml`」综合为同一两档：
  - **审批档**：命名声明注册表（persona 等）住提供方插件 `config.yml`——机器写 = D40 最小 diff 纪律 + 审批事务（ADR-0008 管线原样）。**ADR-0017 Consequences「agent 自我进化的正当出口 = preset revision 通道（机器可写、走审批）」在此兑现**：agent 改 persona = 改配置走审批，审批单位 = 插件目录 diff。
  - **自管档**：高频/临时声明（每会话即兴参数）= 运行时构造或住 `data/`——零审批（判别两问②原样）。
- 核心不指定「哪个插件存、存哪档」；审批覆盖靠作者选对档——引导归 Creator 文档（登记）。
- 种子稿待决 #2（preset 声明/修订的存储位置与审批关系）**结案**。

### S3.3 D63 mount API 与能力门 = 立门 `mount: true`（2026-10-11 用户拍板）

- **API 族**：`ctx.mount(declaration) -> handle`（编排面新方法族）；句柄供 unmount（D64）。参数/返回的 Value 编码细则归 luau-abi living doc（登记）。
- **能力门立 `mount: true`**（capabilities map 新键，`sqlite: true`/`process: true` 同形）：mount = 元权限（激活代码运行）——D26 编排面不立门的间接化论证到此断开：间接化管「调用已激活的」，mount 是「激活新的」。fail-closed 缺省（未声明调用 = 运行时响亮指路 manifest，§A3.2 原样）；纯代码插件无资格（§A1.3 原样）；审批面三栏并示同栏可见（§A9.3 D26.2 面原样）。
- **淘汰**：不立门走编排面惯例（D26）——对称性在「激活新代码」处断开，严格制定调下显式门更合身。
- **演进纪律**：capabilities 词汇 additive 增补 → `abi_rev` bump（seam 状态行既定纪律）；luau-abi §A2.5 修订注（本 change 已同步）；正式进字段面归本任务冻结批次。
- **mount 执行 = 标准启用管线**：部署索引解析 → config 合成校验（含秘密引用解析；细则 S4）→ inject 解析（§A9 三分原样）→ setup。与 boot/热更同一条筋。mount 频率面 = 每会话一次量级（非高频）；mount 消耗（编译 + setup）预算归实现期清单。

### S3.4 D64 生命周期 = 父子账本 + 显式 unmount（2026-10-11 用户拍板）

- **挂载方 fiber = 父**；父死 = 子树随账本 LIFO 结账（ADR-0018 S4 四段论 / ADR-0023 drain 路径原样——实例 unload 不区分原因，同一清理契约）。ADR-0010「子 fiber = 父的 effect」兑现到实例面。
- **显式 unmount 通道**（句柄驱动；API 形状细则归 ABI living doc）。
- **子树实例不参与全局重挂载协调**（D41 作用面 = 部署树；实例 = 独立 fiber 子树 + 独立 `lua_State`）。

### S3.5 D65 快照语义 = 挂载时快照（2026-10-11 用户拍板；消解②坐实 + 种子稿待决 #3/#5 结案）

- **实例创建时固定三样**：声明拷贝 + 配置合成结果 + 代码版本（独立 `lua_State` 天然成立）；随实例死亡释放。
- **声明演进 / `config.yml` 变更 / 被挂载插件热更 → 只影响之后的新挂载**，运行中实例不动——Harness「不抢夺运行中 Agent 的工具」语义以快照达成。（限定：被挂件的更新不动实例；挂载方自身热更 = 父死 = 实例随账本结账，归 D64 面。）
- **revision 引用计数机制不立**（消解②坐实：revision 退化为挂载时一次拷贝，无共享无回收）：种子稿待决 #3 结案 = 无此机制；待决 #5 结案 = 运行中实例持旧树 = 快照天然语义。
- **登记 S4**：实例 inject 的服务提供方重挂载时，epoch 失效（fiber §5）对实例的波及政策。

### S3.6 D66 D7 汇合结案（2026-10-11 用户拍板；ADR-0013/0017 复审点兑现）

- **分界**：spawn = 插件代码自由造**新生命周期单元**（新 VM/新插件，无声明面）——**继续关闭**（插件内部任务 fiber = fiber effect 既有通道，ADR-0010/0017 原样允许，不在此列）；mount = 声明数据驱动 + 装配单素材约束（D61）+ 能力门（D63）——审批链完整（代码在装配单审批面、声明可住 `config.yml` 审批档）。
- ADR-0017「spawn 的第一个真实用户到来时在它的设计场合专门定」= 在此结案：mount = 编程式实例化的唯一通道；通用 `ctx:spawn` 维持关闭（其扩展位原样：将来开放 = 纯增量，fiber 父子关系 arena 本就有）。
- context-events §6 汇合点行修订注重指本文档（本 change 已同步，§S1.6 登记兑现）；ADR-0013/0017 Status 行注归本任务冻结批次。
