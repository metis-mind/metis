## 0. 术语锚点与既定地基

### 0.1 术语锚点（本文档新增；共享术语见 [luau-abi](luau-abi.md) §0 / [seam-capabilities](seam-capabilities.md) §0 / [config-format](config-format.md) §0.1）

- **租户（tenant）**：进程内托管的部署根实例——一份配置树连同其 `plugins/`、secrets、journal 的运行时。静态、文件背书；审批/审计边界按租户划分。
- **部署树（deployment tree）**：租户的配置树运行时实例化（对应种子稿轴 2 的「全局树」行）；静态、文件背书。
- **子树声明（subtree declaration）**：描述「挂哪些插件 + 实例级配置值」的数据。住插件侧，不进 `metis.yml`。
- **子树实例（subtree instance）**：host 按声明实例化的隔离插件子树；挂载语义（快照、账本挂靠、隔离粒度）归 S3 定。
- **动态子树挂载（subtree mount）**：从声明到实例的核心机制（S3 正题）。
- **session / persona**：agent 领域概念、插件层实体，由子树机制搭建；不进核心词汇表。

### 0.2 既定地基（本文档只承接，不重审）

- 部署根布局与配置树 = [ADR-0027](../decisions/0027-config-format.md)（D29–D52；living = [config-format](config-format.md)）：部署根 = 配置树文件所在目录；配置树 = 纯装配单；配置值住插件目录 `config.yml`。
- 子 fiber = 父的 effect（[ADR-0010](../decisions/0010-fiber-core.md)）；Context parent 链预留（[ADR-0013](../decisions/0013-context-scope.md)）；inject 驱动加载排序（[ADR-0001](../decisions/0001-inject-runtime-checks.md)）。
- 判别两问（它变了别的会话该不该跟着变 / 拓扑静态设置还是会话动态偏好）= [session-model](session-model.md) §3 定论，存活：动态偏好永进运行时状态，不进任何 YAML（D53 推论：同样不进子树声明）。
- 机器（模型）写入约束 = [session-model](session-model.md) §3 定论（随 config-format D36 平移后的版本），存活：机器永远碰不到人类层（`metis.yml` 正本与 secrets store）；声明写入的审批通道归 S3。
- 结构性隔离论证与轻/重分离论证 = [session-model](session-model.md) §6 定论，存活：前者是子树实例「每插件独立 `lua_State`」的机制输入（S3）；后者的租户级含义（跨租户重资源共享）归 S2 登记。
- D7 编程式 spawn 禁令（[ADR-0017](../decisions/0017-programmatic-spawn-deferred.md)）：插件代码内 `ctx:spawn` 的门关闭；「host 按声明实例化 ≠ 插件 spawn」的汇合点归 S3 正式定。

## S1 正名与用例归位（2026-10-11 收官）

### S1.0 边界与前提

本题定：机制定位与命名、三个用户用例（project / persona / session）的归位层级、议题地图。不归本题：租户托管细则（S2）、声明形状与挂载机制（S3）、实例配置与隔离边界（S4）、v1 范围（S5）。前提：任务 4 已冻结（ADR-0027）；用户定调 = 核心只提供抽象机制，领域概念归插件层。

### S1.1 D53 机制定位与命名（2026-10-11 用户拍板）

- 核心提供且仅提供**两层实例机制**：**租户托管**（静态、文件背书，S2）与**动态子树挂载**（动态、声明背书，S3/S4）。session/persona/project 等领域词不进核心词汇表——session/persona 是插件层用子树机制搭建的概念，project 是部署层的租户。
- 子树声明是数据，住插件侧；不进 `metis.yml`——配置树保持纯装配单（D31/D33 不动）。
- 机制默认**不要求遮蔽语义**：isolate（同 key 服务按子树换实现）是 S4 的独立复审题（luau-abi §A2.3 D32 登记触发器，复审排入 S4）；默认 = 全局服务解析不变。
- **命名定案**：租户（tenant）/ 子树声明 / 子树实例 / 动态子树挂载（subtree mount）。任务 5 改名「实例模型」。
- **session 归位结案**：session = 插件层实体（luau-abi §A6.7「核心是否有 session 概念 = 任务 5 待决 #1」在此结案：核心无 session 概念，只有 fiber 子树与子树实例）；journal 条目是否押实例字段的形态复审归 S4（A6.7 注入保留）。

### S1.2 D54 project 用例 = 单进程多租户（2026-10-11 用户拍板）

- 学习/财务管理类「项目」差异的性质 = 整套装配、数据、secrets、journal 审计边界全不同 → 归位 = **租户**（部署层）。
- 托管形态 = **单进程多租户**：一个 server 进程托管多个部署根。用户拍板理由 = 管理统一，不维护多个服务（淘汰本议题初议的「多进程零新机制」推荐——多进程买到的隔离/崩溃边界免费，单进程内由 host 以故障域隔离与统一 status 面补回；跨项目协作走网络不变）。
- 每租户 = 独立配置树 / `plugins/` 树 / secrets / journal / 审批域；部署根布局（D29）原样适用于每租户。
- **淘汰**：① 多进程每项目一 server（见上）；② 单树多项目（一套配置管多项目 = 用户明确排除的混乱形态）。
- **术语注意**：此「项目/租户」与 config-format C5/D44 砍掉的 workspace（fs 绑定机制）无关，勿混。
- 机制细则（租户来源、增删时机、隔离与故障域、管理面、跨租户政策）归 S2；`--config` 语义扩展登记 = §S1.6。

### S1.3 D55 persona 用例 = 插件层归位（2026-10-11 用户拍板）

- **两读法记录**：(a) **纯数据路由**——persona = 一份命名数据（提示词、工具子集、模型参数），注册表住 agent 插件的 `config.yml`（审批可见）或 `data/`（自管），工具差异 = 工具路由插件按 persona 名过滤，零核心机制；(b) **子树实例**——persona = 一份子树声明（真·不同插件组合 + 实例配置值），每次会话实例化一份。
- **判读**：(a) 覆盖常态（人设差异多为数据差异）；(b) 是重武器（组合差异时才用）。两者都不需要核心内置 persona 概念，机制设计不为 persona 弯腰。
- **机制需求下限**（冻结为 S3 输入要求）：子树声明须能表达「不同插件集 + 不同实例配置值」。
- persona 建模（注册表形状、选择界面、审批策略）= 插件层议题，不进本任务冻结面。

### S1.4 重构带来的消解与种子稿条款映射（2026-10-11 沉淀）

- **消解①**：种子稿 §6「project 与身份的优先级冲突」——project 归租户层、身份（persona）归部署内声明后，两者不再同层竞争，问题消失。
- **消解②（候选，S3 正式拍）**：Harness 的 revision 引用计数机制或整体不需要——若挂载语义 = 挂载时快照（实例创建时复制声明并钉住代码版本），声明更新天然只影响之后的新挂载，「revision」退化为一次拷贝，回收机制不立。
- **消解③**：种子稿 §6 的「叠加 vs 选择」keyed merge 设想与「不同会话不同配置的三个来源」——随 D54/D55 归位事实消解：身份差异 = 子树声明内容（S3 形状题）或纯插件数据（D55(a)），不再需要独立的 merge 栈设想；「三个来源」的残余 = 声明选择 / 声明演进 / 运行时状态（判别两问兜底），不再单列。
