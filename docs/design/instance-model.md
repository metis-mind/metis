## 0. 术语锚点与既定地基

### 0.1 术语锚点（本文档新增；共享术语见 [wit-abi](wit-abi.md) §0 / [seam-capabilities](seam-capabilities.md) §0 / [config-format](config-format.md) §0.1）

- **租户（tenant）**：进程内托管的部署根实例——一份配置树连同其 `plugins/`、secrets、journal 的运行时。静态、文件背书；审批/审计边界按租户划分。
- **部署树（deployment tree）**：租户的配置树运行时实例化（对应种子稿轴 2 的「全局树」行）；静态、文件背书。
- **租户树（tenant tree）**：租户的 fiber 运行时树——host 根 fiber（托管进程的总根）的子树（ADR-0010）。与部署树是同一租户的两个侧面：部署树 = 配置侧实例化，租户树 = 运行时侧实例化。
- **子树声明（subtree declaration）**：描述「挂哪些插件 + 实例级配置值」的数据。住插件侧，不进 `metis.yml`。
- **子树实例（subtree instance）**：host 按声明实例化的隔离插件子树；挂载语义（快照、账本挂靠）= S3 定（D64/D65），隔离粒度（服务解析作用域）= S4 定（D68）。
- **动态子树挂载（subtree mount）**：从声明到实例的核心机制（S3 正题）。
- **实例作用域（instance scope）**：子树实例的服务解析作用域（D68）——实例内 provide 住此；inject 沿 parent 链先查自己作用域、再逐级向上。
- **session / persona**：agent 领域概念、插件层实体，由子树机制搭建；不进核心词汇表。

### 0.2 既定地基（本文档只承接，不重审）

- 部署根布局与配置树 = [ADR-0027](../decisions/0027-config-format.md)（D29–D52；living = [config-format](config-format.md)）：部署根 = 配置树文件所在目录；配置树 = 纯装配单；配置值住插件目录 `config.yml`。
- 子 fiber = 父的 effect（[ADR-0010](../decisions/0010-fiber-core.md)）；Context parent 链预留（[ADR-0013](../decisions/0013-context-scope.md)）；inject 驱动加载排序（[ADR-0001](../decisions/0001-inject-runtime-checks.md)）。
- 判别两问（它变了别的会话该不该跟着变 / 拓扑静态设置还是会话动态偏好）已成定论：动态偏好永进运行时状态，不进任何 YAML（D53 推论：同样不进子树声明）。
- 机器（模型）写入约束已成定论（随 config-format D36 平移后的版本）：机器永远碰不到人类层（`metis.yml` 正本与 secrets store）；声明写入的审批通道归 S3。
- 结构性隔离论证与轻/重分离论证已成定论：前者是子树实例「每插件独立组件实例（Store+Instance）」的机制输入（S3）；后者的租户级含义（跨租户重资源共享）= D59（S2）。
- D7 编程式 spawn 禁令（[ADR-0017](../decisions/0017-programmatic-spawn-deferred.md)）：插件代码内 `ctx:spawn` 的门关闭；「host 按声明实例化 ≠ 插件 spawn」的汇合点归 S3 正式定。

## S1 正名与用例归位

### S1.0 边界与前提

本题定：机制定位与命名、三个用户用例（project / persona / session）的归位层级、议题地图。不归本题：租户托管细则（S2）、声明形状与挂载机制（S3）、实例配置与隔离边界（S4）、v1 范围（S5）。前提：配置格式已冻结（ADR-0027）；用户定调 = 核心只提供抽象机制，领域概念归插件层。

### S1.1 D53 机制定位与命名

- 核心提供且仅提供**两层实例机制**：**租户托管**（静态、文件背书，S2）与**动态子树挂载**（动态、声明背书，S3/S4）。session/persona/project 等领域词不进核心词汇表——session/persona 是插件层用子树机制搭建的概念，project 是部署层的租户。
- 子树声明是数据，住插件侧；不进 `metis.yml`——配置树保持纯装配单（D31/D33 不动）。
- 机制默认**不要求遮蔽语义**：isolate（同 key 服务按子树换实现）不立字段，遮蔽语义由实例作用域天然给出（D68/D69）；部署树全局服务解析不变。
- **命名定案**：租户（tenant）/ 子树声明 / 子树实例 / 动态子树挂载（subtree mount）。任务 5 改名「实例模型」。
- **session 归位结案**：session = 插件层实体（核心无 session 概念，只有 fiber 子树与子树实例）；journal 条目不押实例字段（D72）。

### S1.2 D54 project 用例 = 单进程多租户

- 学习/财务管理类「项目」差异的性质 = 整套装配、数据、secrets、journal 审计边界全不同 → 归位 = **租户**（部署层）。
- 托管形态 = **单进程多租户**：一个 server 进程托管多个部署根。用户拍板理由 = 管理统一，不维护多个服务（淘汰本议题初议的「多进程零新机制」推荐——多进程买到的隔离/崩溃边界免费，单进程内由 host 以故障域隔离与统一 status 面补回；跨项目协作走网络不变）。
- 每租户 = 独立配置树 / `plugins/` 树 / secrets / journal / 审批域；部署根布局（D29）原样适用于每租户。
- **淘汰**：① 多进程每项目一 server（见上）；② 单树多项目（一套配置管多项目 = 用户明确排除的混乱形态）。
- **术语注意**：此「项目/租户」与 config-format C5/D44 砍掉的单数 workspace（fs 绑定机制）无关，勿混；命名根随后撤回（[ADR-0039](../decisions/0039-fs-capability-two-tier.md)），fs = private 隐式 / global 声明。

### S1.3 D55 persona 用例 = 插件层归位

- **两读法记录**：(a) **纯数据路由**——persona = 一份命名数据（提示词、工具子集、模型参数），注册表住 agent 插件的 `config.yml`（审批可见）或 `data/`（自管），工具差异 = 工具路由插件按 persona 名过滤，零核心机制；(b) **子树实例**——persona = 一份子树声明（真·不同插件组合 + 实例配置值），每次会话实例化一份。
- **判读**：(a) 覆盖常态（人设差异多为数据差异）；(b) 是重武器（组合差异时才用）。两者都不需要核心内置 persona 概念，机制设计不为 persona 弯腰。
- **机制需求下限**（冻结为 S3 输入要求）：子树声明须能表达「不同插件集 + 不同实例配置值」。
- persona 建模（注册表形状、选择界面、审批策略）= 插件层议题，不进本任务冻结面。

### S1.4 重构带来的消解与种子稿条款映射

- **消解①**：种子稿 §6「project 与身份的优先级冲突」——project 归租户层、身份（persona）归部署内声明后，两者不再同层竞争，问题消失。
- **消解②（坐实 = D65）**：Harness 的 revision 引用计数机制整体不立——若挂载语义 = 挂载时快照（实例创建时复制声明并钉住代码版本），声明更新天然只影响之后的新挂载，「revision」退化为一次拷贝，回收机制不立。
- **消解③**：种子稿 §6 的「叠加 vs 选择」keyed merge 设想与「不同会话不同配置的三个来源」——随 D54/D55 归位事实消解：身份差异 = 子树声明内容（S3 形状题）或纯插件数据（D55(a)），不再需要独立的 merge 栈设想；「三个来源」的残余 = 声明选择 / 声明演进 / 运行时状态（判别两问兜底），不再单列。

## S2 租户托管

### S2.0 边界与前提

本题定**租户托管的机制细则**：租户来源、增删时机、隔离与故障域、跨租户政策、管理面与标识。不归本题：子树声明与挂载（S3）；实例配置与服务解析边界（S4）；v1 范围（S5）。前提：D54（project = 单进程多租户）；ADR-0023（进程级干净重启、无重启专有钩子）；部署根布局（D29）原样适用于每租户。

### S2.1 D56 租户来源 = `--config` 单租户 + `--fleet-dir` 舰队目录

- **`--config` = 单租户模式，现状零变化**（D29 原样）。
- **`--fleet-dir <dir>` = 多租户模式**：直接子目录中含 `metis.yml` 者 = 租户（一级扫描，不递归）；**租户名 = 子目录名**（扫描唯一性构造保证，重名不可能）。无 `metis.yml` 的子目录 = 静默忽略 + `metis check` 提示级列出（D34 未装配件政策同族：目录里多个目录不是核心的管辖事项，写码期教具提示）。
- **两旗标互斥**：同给 = 响亮报错（二选一不含糊）。
- **淘汰**：① host 配置文件（新文件种类 + 新分层的税，fleet 目录「目录即列表」零仪式平替）；② `--config` 可重复（租户集持久化推给启动行、basename 重名自管、顺序语义含糊——fleet 目录全解）；③ 递归扫描（隐式魔法）。
- **联动**：config-format §C1.1 D29（本文件已同步）。

### S2.2 D57 租户集 = boot-only

- **增删租户 = 改 fleet 目录 + 进程干净重启**（ADR-0023 路径原样：全量 unload → 全量 load，无重启专有钩子；租户树生命周期复用同一条 drain/load 筋）。
- **代价明写**：重启中断全部租户的运行中会话（进程死则组件实例全灭，ADR-0023 Consequences；跨重启连续性 = fiber §10 登记 + journal——方向 = fresh-start（[journal](journal.md) D75），细则 = J3 D84–D88：fresh-start 写实清单 + 崩溃自证 + 实例不自动复活；「会话连续性归插件层持久化」不变）。缓解：重启秒级；会话本质是短命子树实例（S3），其连续性归插件层持久化（此缓解以 S3 生命周期语义成立为前提；若 S3 反案则缓解弱化，运行时控制通道扩展位权重上升）。
- **淘汰**：v1 立运行时增删（需要 host 控制通道 = IPC/admin endpoint + 协议 + 鉴权一整套新机器）。
- **扩展位**：运行时租户控制通道；触发器 = 真实的「不中断增删」需求。

### S2.3 D58 隔离与故障域

- **租户 = host 根 fiber 下的独立租户树**（术语 §0.1；子 fiber = 父的 effect，ADR-0010 原样）。**每租户独立实例**：服务注册表、事件总线、部署索引、journal、secrets。
- **故障域 = 租户树**：单租户启用/运行失败 = 该租户 Failed + host warn 指路，不拖垮舰队。
- **多租户细化**：fleet 模式下单租户配置（`metis.yml`/`overlay.yml`/`secrets.yml`/`values.yml`）解析失败 = 该租户 Failed、其余照常 boot；**单租户模式维持「响亮拒启动」原样**（config-format §C3.2 / §C6.2 D47）。
- **预算**：fiber 预算机制树粒度原样（租户 = 天然预算根）；跨租户配额/公平性 = 不立（扩展位，触发器 = 真实多租户争用需求）。
- **诚实边界**：核心代码 panic = 进程级，多租户不隔离此类失败。

### S2.4 D59 跨租户政策 = 默认零共享

- **无跨租户 inject / 事件 / fs**。跨项目协作 = 网络（HTTP 客户端插件调另一租户的插件 endpoint）——与多进程方案同一通道，不多买机器。
- **重资源**（llm 连接池等）= 每租户自实例，复制代价明记——种子稿「轻/重分离」论证的租户级落地：实例开销不是事，重资源复制才是；真痛了 → 共享服务独立部署（一个「基础设施租户」/独立进程）被网络调用。
- **扩展位**：跨租户共享插件实例；触发器 = 真实需求。

### S2.5 D60 管理面与标识

- **v1 三件套**：① host 日志面——租户状态变迁（Loading → Running / Failed + 原因指路）进 host tracing；Failed = 需人为动作的态，warn 政策同 W9 章（状态变迁当场一条 + 每 boot 一次）；② `metis check` 静态校验 fleet 目录（登记工具面）；③ 端口/endpoint 每租户自管——插件 `config.yml` 各配各的，核心零路由机器（多租户不引入路由层）。
- **运行时 status 查询通道**（admin endpoint / IPC）= 扩展位，触发器 = 总览/前端需求真实出现。
- **journal = 每租户一本**（D54 推论落地）：段文件在各租户部署根 `journal/`（D29 布局零改动）；条目本体无需租户字段（物理分离天然解决）；journal 属主 = host 托管 N 本、每租户一本。

## S3 声明与挂载

### S3.0 边界与前提

本题定**从声明到实例的机制**：声明形状与素材约束、住处与审批关系、mount API 与能力门、生命周期、快照语义、D7 汇合结案。不归本题：实例配置 overlay 的合成与校验细则（S4）、子树内服务解析边界与 isolate 复审（S4）、实例标识与 journal 字段（S4）。前提：D53（机制定位）、D55（需求下限 = 声明须能表达「不同插件集 + 实例配置值」）；ADR-0017（D7 spawn 禁令与汇合登记）；ADR-0010（子 fiber = 父的 effect）。

### S3.1 D61 声明形状与素材约束

- **声明 = Value 数据**（mount 的输入；YAML 等价形示意）：

```yaml
plugins: # list 形——允许同 key 多实例（各带不同 overlay）
    - use: memory # 装配单 key 引用
      config: { ... } # 实例配置 overlay（可选；合成与校验细则 = D67）
    - use: blog-writer
```

- **素材约束**：`use` ⊆ **本租户**装配单（**enabled ∪ 休眠件**）。引用未装配件 = 挂载时响亮报错（D34 同族，「目录存在但树无 entry」指路面复用）；引用查无（目录都不存在）= 同族响亮、与未装配措辞两分（D34 既定区分原样）。**休眠件新角色 = 只供子树挂载的插件**——审批面完整保持：一切可运行代码都在装配单可见（休眠件的 capabilities 同进审批 diff）。
- **淘汰**：① 自包含声明（自带插件定义——违反目录单形态 D35，代码住处唯一 = 插件目录）；② 引用任意部署索引目录（审批后门：未装配件的 capabilities 从未进过审批面）。
- 实例化顺序 = inject 图驱动（ADR-0001 复用）；list 书写序只是书写序。
- 机制需求下限（D55）验收：声明能表达「不同插件集 + 不同实例配置值」✅。

### S3.2 D62 声明住处 = D36 两档分工平移

- **核心只定义声明形状（mount 输入格式）；住处 = 插件层议题**——不立任何新文件种类/新格式，与 D36「配置值住处 = 插件目录 `config.yml`」综合为同一两档：
  - **审批档**：命名声明注册表（persona 等）住提供方插件 `config.yml`——机器写 = D40 最小 diff 纪律 + 审批事务（ADR-0008 管线原样）。ADR-0017 Consequences「agent 自我进化的正当出口 = preset revision 通道（机器可写、走审批）」在此兑现：agent 改 persona = 改配置走审批，审批单位 = 插件目录 diff。
  - **自管档**：高频/临时声明（每会话即兴参数）= 运行时构造或住 `data/`——零审批（判别两问②原样）。
- 核心不指定「哪个插件存、存哪档」；审批覆盖靠作者选对档——引导归 Creator 文档（登记）。
- 种子稿待决 #2（preset 声明/修订的存储位置与审批关系）结案。

### S3.3 D63 mount API 与能力门 = 立门 `mount: true`

- **API 族**：`ctx.mount(declaration) -> handle`（编排面新方法族）；句柄供 unmount（D64）。declaration 的编码 = TLV `Value`（[wit-abi](wit-abi.md) W6 D160/D162：mount 声明不走 blob 车道）；不透明句柄形态 = `mount-handle` resource（W3 D150）。
- **能力门立 `mount: true`**（capabilities map 新键，`process: true` 同形）：mount = 元权限（激活代码运行）——D26 编排面不立门的间接化论证到此断开：间接化管「调用已激活的」，mount 是「激活新的」。fail-closed 缺省（未声明调用 = 运行时响亮指路 manifest，W3 章原样）；零仪式插件无资格（W1 章原样）；审批面三栏并示同栏可见（W9 章原样）。
- **淘汰**：不立门走编排面惯例（D26）——对称性在「激活新代码」处断开，严格制定调下显式门更合身。
- **演进纪律**：capabilities 词汇 additive 增补 → WIT package version 演进（[wit-abi](wit-abi.md) W10 章 = T13-p）；正式进字段面 = [ADR-0028](../decisions/0028-instance-model.md) 批次 #1。
- **mount 执行 = 标准启用管线**：部署索引解析 → config 合成校验（含共享变量解析，含 secret；C6.4 D135 / 细则 = D67）→ inject 解析（W9 章三分原样）→ setup。与 boot/热更同一条筋。mount 频率面 = 每会话一次量级（非高频）；mount 消耗（编译 + setup）预算归实现期清单。

### S3.4 D64 生命周期 = 父子账本 + 显式 unmount

- **挂载方 fiber = 父**；父死 = 子树随账本 LIFO 结账（ADR-0018 S4 四段论 / ADR-0023 drain 路径原样——实例 unload 不区分原因，同一清理契约）。ADR-0010「子 fiber = 父的 effect」兑现到实例面。
- **显式 unmount 通道**（句柄驱动；API 形状细则归 ABI living doc）。
- **子树实例不参与全局重挂载协调**（D41 作用面 = 部署树；实例 = 独立 fiber 子树 + 独立组件实例）。
- **重启后实例不自动复活**（[journal](journal.md) D87）：mount 声明 = 文件背书（D62 审批档住挂载方 `config.yml`）——boot 全量 load 后挂载方 setup 重跑 = 重新 `ctx.mount`，天然幂等；复活的新挂载拿新快照（D65 原位）；运行时构造的自管档声明不复活（易失物，挂载方自行重建）。

### S3.5 D65 快照语义 = 挂载时快照

- **实例创建时固定三样**：声明拷贝 + 配置合成结果 + 代码版本（独立组件实例天然成立）；随实例死亡释放。
- **声明演进 / `config.yml` 变更 / 被挂载插件热更 → 只影响之后的新挂载**，运行中实例不动——Harness「不抢夺运行中 Agent 的工具」语义以快照达成。（限定：被挂件的更新不动实例；挂载方自身热更 = 父死 = 实例随账本结账，归 D64 面。）
- **revision 引用计数机制不立**（消解②坐实：revision 退化为挂载时一次拷贝，无共享无回收）：种子稿待决 #3 结案 = 无此机制；待决 #5 结案 = 运行中实例持旧树 = 快照天然语义。
- **登记 S4**：实例 inject 的服务提供方重挂载时，epoch 失效（fiber §5）对实例的波及政策 = D70。

### S3.6 D66 D7 汇合结案

- **分界**：spawn = 插件代码自由造**新生命周期单元**（新组件实例/新插件，无声明面）——**继续关闭**（插件内部任务 fiber = fiber effect 既有通道，ADR-0010/0017 原样允许，不在此列）；mount = 声明数据驱动 + 装配单素材约束（D61）+ 能力门（D63）——审批链完整（代码在装配单审批面、声明可住 `config.yml` 审批档）。
- ADR-0017「spawn 的第一个真实用户到来时在它的设计场合专门定」= 在此结案：mount = 编程式实例化的唯一通道；通用 `ctx:spawn` 维持关闭（其扩展位原样：将来开放 = 纯增量，fiber 父子关系 arena 本就有）。
- context-events §6 汇合点行指向本文件；ADR-0013/0017 Status 行注见 ADR-0028。

## S4 实例配置与隔离

### S4.0 边界与前提

本题定**实例配置与隔离边界**：实例配置 overlay 合成校验、服务解析边界、isolate/重命名/intercept/group 复审结案、epoch 失效波及政策、事件跨界、实例标识与 journal 字段、journal-replay 开放问题 6 结案。不归本题：v1 范围（S5；种子稿待决 #4 的「同期与否」半）。前提：D61（声明形状 = `use` + `config:` overlay）；D63（mount 执行 = 标准启用管线复用）；D64（挂载方 fiber = 父）；D65（快照语义 + epoch 波及登记）；ADR-0013（Context parent 链预留，D2 半归本题）。

### S4.1 D67 实例配置 overlay 合成与校验（config-format §C2.9 张力结案）

- **合成 = `config.yml`（base）∪ 声明 `config:`（实例补丁），字段级稀疏合并**——D38 语义原样复用：overlay 提到的字段赢、未提到零意见；声明无 `config:` ≡ `{}`。
- **校验 = D36 同一管线同一校验器**：manifest schema 校验（缺 required / 类型错 / 多给键 = 响亮）→ 共享变量解析（`$value` 含 secret；C6.4 D135）→ 默认值合成；时机 = mount 时（D63「mount 执行 = 标准启用管线复用」原位——配置合成校验 = 其中一站，无新时机概念）；失败 = 挂载当场响亮报错，该插件不激活。
- **共享变量政策零分叉**：overlay 允许写 `{ $value: "name" }`（含 secret）——解析管线跟值走，不看声明住哪档（审批档 / 自管档同规则）；秘密写明文 = 校验拒绝（D36 同族）。
- **快照联动**：合成结果随实例固定（D65 原位）；挂载后 `config.yml` 热更只影响之后的新挂载，运行中实例不动。
- **淘汰**：① 实例 overlay 全量替代 `config.yml`（实例背全量配置 = 重复税，部署级默认值失效）；② overlay 不校验直接进实例（快照里藏错，严格制不容）；③ 实例配置第三住处/第三档（D62 两档已结案）。
- **明记代价**：自管档声明（运行时构造，零审批 = D62）可携带秘密引用——「哪个秘密名绑给被挂件」由挂载方代码运行期决定，不进审批 diff（部署级通道里此绑定经 `config.yml` 审批可见）。缓解面：挂载方须持 `mount` 门、被挂件 schema 须声明 `secret: true` 键（审批面可见「可能吃秘密」）、素材 ⊆ 装配单（D61）。收紧路径（秘密引用限审批档声明）登记扩展位，触发器 = 真实滥用担忧。

### S4.2 D68 服务解析边界 = 实例作用域 + parent 链向上

- **问题写实**：全局注册表单级查找（v1 原样）在子树面前两处撞墙——① 实例内 provide 若进租户级注册表，同 key 多实例 = 撞名响亮（W9 章撞名判定），D61 list 形多实例作废；② 实例若全闭环，inject 够不到部署树重资源（llm 每租户一份，D59 轻/重分离）。
- **实例 = 服务解析作用域**：实例内 provide 住实例作用域，不进租户级注册表（service-registry §1 `ScopeTag` 预留位在此兑现）。
- **inject 解析 = 沿 fiber parent 链先查自己作用域、逐级向上、租户注册表兜底**——ADR-0013 Consequences 登记加回路径原话「服务查找沿 parent 链先查自己」；mount 根 fiber 的父 = 挂载方 fiber（D64），链天然接通。
- **可见性 = 向上单向**：兄弟实例互不可见；挂载方不能向下 inject 实例内服务。向下通信 = 事件总线（`serial` 派发 = 请求-响应形态既定，W3 章）；**扩展位**：mount handle 服务面出口（触发器 = 真实摩擦）。
- **判定面精确化**：provide 撞名与判环的判定作用面 = **同作用域内**已启用 ∪ Pending——跨作用域同 key = 遮蔽不是撞名；跨层 inject 边恒向上（向下/兄弟无边）→ 跨层结构性无环。inject 缺失三分的提供方可见集 = 沿 parent 链可达集；不可见（含兄弟/子实例提供方）= 同族启用期响亮。
- **淘汰**：① 全局单级不变（多实例共存死）；② 实例全闭环（重资源复制到实例级）；③ 显式 import/export 可见性清单（新词汇 + 新审批面，v1 无用户；遮蔽序已够表达）。
- **联动**：W9 章（T13-o）承接判定面三处（可见集 / 撞名作用面 / 判环图；ADR-0028 批次 #3）；context-events §5 已同步。

### S4.3 D69 isolate/重命名/intercept/group 复审结案

- **触发器兑现**：D32 登记「四件不立，触发器 = 首个真实撞名需求或子树落地，同批复审」——子树已落地（S3），同批复审。
- **isolate（同 key 服务按子树换实现）= 不立字段，语义由 D68 天然给出**：实例内挂同 key 提供方即换实现（先查自己 = 遮蔽序）；Cordis `isolate: true` 声明域由实例作用域结构性覆盖。service-registry 的「多实现 / 扩容」推迟项同案结案：多实现 = 不同实例作用域各一份；同作用域内唯一性与按到达开始处理原样。
- **部署侧重命名 = 维持不立**：实例作用域已缓解撞名（不同实例各挂同 key 不撞）；部署树内撞名仍 = 部署者二选一（D32 原案）；「首个真实撞名需求」半未触发。
- **intercept（Cordis：给某服务名下所有后代合并配置）= 不立**：职能由 D67 声明 `config:` overlay 覆盖；「服务名下后代」语义在 fiber 树模型下无对应物。
- **group/嵌套子树字段 = 不立**：子树实例 = fiber 树天然嵌套（实例内可再 mount，`mount` 门管控 = D63）；配置树无对应需求。
- **D31 已知牺牲复审**：同插件多实例的实例面答案 = D61 list 形（各带不同 overlay）；部署级维持复制目录原样（缓解不移除）。配置树 entry 封闭集 `{ enabled }` 不动。
- 种子稿待决 #4 的「机制复审」半在此结案；「v1 同期与否」半 = 消解（无字段可谈同期，D74）。

### S4.4 D70 epoch 失效波及政策 = 穿透到消费者粒度

- **穿透**：实例内插件 inject 的提供方重挂载 → epoch+1 → 失效级联沿 inject 边原样进实例；粒度 = **实例内消费者 fiber**（该插件卸载 + 重跑 setup、拿新烘焙句柄快照）。
- **快照三样不动**：重跑 setup 用快照里的配置合成结果（不重读 `config.yml`）与快照代码版本；刷新的只是外部提供方句柄——D65 快照面 = 被挂件自身三样，不涉外部提供方，本决补全此缺口。
- **纪律零分叉**：与部署树消费者同一 epoch 纪律；顺序 = fiber §5 第 4 条原样（先卸消费者含实例内、再卸提供方；加载反向）。
- **淘汰**：① 实例豁免（epoch 不在调用路径校验（ADR-0018 S5），陈旧句柄调新提供方 = 方法集漂移静默化，严格制不可开此口）；② 整实例随父重建（会话状态无辜陪葬，粒度超必要——D57 缓解注「会话 = 短命子树」依赖实例稳定）。
- **明记代价**：外部提供方热更打断实例内消费者插件的内存态（状态三分纪律既定：丢不起的状态走显式落盘/状态服务）。

### S4.5 D71 事件跨界 = 不立实例事件作用域

- **事件 = 开放广播，无表可查**（**已兑现 = [wit-abi](wit-abi.md) W8 D173–D179**：emit 不保证有人听、观测类插件「听一切」一等用法、listen 面运行期不强制）——「解析边界」在服务面成立（有注册表可查），在事件面无对应物。
- **实例内 on/emit 直上租户事件总线**（D58 每租户独立不动）；实例 fiber 的 `internal/plugin` 生命周期事件照常进总线（观测面完整）。
- **会话/persona 级路由 = payload 参数化 + selector 模式**：W8 章既定引导（静态事件名 + 实例参数进 payload，如 `ctx.emit("session/input", { session_id = ... })`）；可编程路由 = 普通插件（context-events §2.1 既定，host 只供四种硬编码默认策略）。
- **明记代价**：同租户内跨实例事件**互相可见**——按 payload 字段过滤是监听者自己的责任；信息流入面的审批可见面 = manifest `events listen` 名单（意图展示，不是运行期白名单；`events publish` 出流另列；[wit-abi](wit-abi.md) W8 D174）；实例插件名单随装配单审批面可见（D61 素材约束已保证）。
- **淘汰**：实例事件命名空间（广播语义被切碎；selector 已提供可编程路由；工具/审计插件跨实例观测被误伤）。

### S4.6 D72 journal 实例字段结案 + 实例标识

- **journal 条目不押实例字段**——既定倾向平移结案：条目只靠 fiber/plugin 标识 + 因果链；「找出某实例的日志」= 查询侧按子树根 fiber id 归组，聚合归查询侧/插件层。每租户一本（D60）、逻辑单流全不动。
- **实例标识 = 挂载根 fiber id**（结构性存在，零新机制）；实例「名字」= persona 等插件层概念，不进核心词汇表（D53 原样）。
- **人读面**：mount/unmount 时 host 日志各一条（根 fiber id + 挂载方 + 声明来源指路 + 插件集摘要）——W9 章 warn 哲学同族（管理动作当场可见，不周期重发）。
- **淘汰**：条目押实例字段（每条目背冗余税，聚合并未因此变易；实例无名字概念可押）。
- **联动**：journal.md D76/D78 + 本文件 D72；W8 章（T13-n）**已兑现（2026-10-19）= [wit-abi](wit-abi.md) W8 D173–D179**；事件面不新增 journal 字段。

### S4.7 D73 journal-replay 开放问题 6 结案 = 维持内部流量

- **结案**：跨实例服务调用在 D68 边界下**结构性不存在**（兄弟互不可见、向下无 inject）；唯一跨边界服务流量 = 实例沿 parent 链上调租户服务 = 同租户树内部流量——`service_call`/`service_result` 族维持「内部流量」结论（kind 表 SSOT = [journal](journal.md) D78；内部流量族 v1 撤销 = D84 骨架化，故不立记录面；「内部流量」结论本体不动）。
- **扩展位登记**：「跨租户共享插件实例」（D59 扩展位）或 handle 服务面出口（D68 扩展位）将来开放时，边界输入问题重开。
- **联动**：journal-replay-research 开放问题 6 标结注已同步。

## S5 v1 范围与收口

### S5.0 边界与前提

本题定 **v1 范围收口与冻结批次**：种子稿待决 #4「同期与否」半结案、§5/§6 范围登记结案、冻结批次 manifest 与形态。前提：S1–S4 全收官（D53–D73）。

### S5.1 D74 v1 范围结案

- **v1 设计范围 = 任务 5 全部机制**：租户托管（D56–D60）+ 动态子树挂载（D61–D66）+ 实例配置与隔离（D67–D73）。理由：mount 是 ADR-0017 登记的自我进化正当出口（D62），裁掉它 Creator 模式只能改现有插件、不能激活新组合；四站机制互相咬合，无可裁子集。
- **待决 #4 结案 = 消解**：isolate/intercept/group/重命名不立 = 永久结案非推迟（D69）——无字段可谈「同期」，isolate 语义随子树天然在场（D68 遮蔽序）。
- **种子稿 §5「v1 最小集建议 / preset 留设计位」与 §6「v1 范围是否扩大」登记同案结案**。
- **扩展位不进 v1**、原样存活：运行时租户控制通道（D57）/ 跨租户配额（D58）/ 跨租户共享插件实例（D59）/ 运行时 status 通道（D60）/ handle 服务面出口（D68）/ 秘密引用限审批档（D67）。
- **实现排期不进冻结面**：实现期清单归各站登记与任务队列原位。
- **淘汰**：回种子稿建议（v1 不含子树挂载）——mount 砍掉 = 自我进化出口关闭，与 ADR-0008/0017 立意冲突。
