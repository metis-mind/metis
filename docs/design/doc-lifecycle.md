# Metis — 文档生命周期与防膨胀（living doc）

> 状态：✅ 冻结面 = [ADR-0033](../decisions/0033-doc-lifecycle.md)（2026-10-14）；本文档为 living doc（教义面，read-mostly）。演进纪律：additive 增补（清单细化、新扩展位登记）落本文档修订注；破坏式变更（状态机改写、闸门废除、人类决策点变更）走新 ADR supersede。
> Last reviewed: 2026-10

## 1. 定位：膨胀是双重税

1+N 模式下文档膨胀收两道税：维护者付注意力税，agent 付上下文窗口税；文档质量还直接决定 agent 产出质量（垃圾进垃圾出）。问题由维护者原话立项（火-2，2026-10-14）：「我们的整个结构，落到文档的地方，不管是否是用户看的地方，我们都需要有一个机制来防止其膨胀。目前HANDOFF的膨胀就很严重，以及docs里面的文档的膨胀也很严重，里面有一些是重复逻辑的出现，有一些是没有记录价值信息的堆叠，以及一些我没有想到的问题。这里是文档维护的责任，也是我们在架构设计之初就应该考虑的问题，这应该也是调研的一部分」。

调研依据 = [review-economics-research](../research/review-economics-research.md) RQ8 章（五个知识传统 → 四类机制候选清单；结论：入口闸门是行业标配，存量生命周期是行业默认缺口）；仓内对账 = [review-economics-rq6-inventory](../research/review-economics-rq6-inventory.md)。本文档只立存量侧机制，入口侧既有闸门（三问过滤器 / 长度预算 / 孤儿检查）原位不动。

症状三分类 → 机制应答：

| 症状（火-2）           | 机制应答                                                      |
| ---------------------- | ------------------------------------------------------------- |
| 重复逻辑的出现         | canonical 指定 + 废弃标记优于沉默（§6）；冗余候选对巡检（§5） |
| 没有记录价值信息的堆叠 | 三问过滤器（入口既有）+ 归档态（§2）+ 压缩仪式（§7）          |
| 我没有想到的问题       | gardener 巡检的发现位（§5）+ 机器信号扩展位（§8）             |

## 2. 生命周期状态机：现役 ↔ 归档 + 删除闸

适用范围：归档态横切 `docs/design/` 与 `docs/research/`。`docs/decisions/` 的归档等价物 = 既有 `superseded by` 标记；`docs/backlog.md` 每会话收尾自刷新、收官行到期离库走压缩仪式微缩版（纪律 SSOT = 其[读写纪律](../backlog.md)；2026-10-15 修订注），豁免。

- **现役**：文档在 AGENTS.md 地图持正常条目，默认可读。
- **归档**：状态头标 `📦 已归档（YYYY-MM-DD）` + 归档原因 + 去向指针（存活内容在哪承接）；AGENTS.md 地图条目同步加 `archived` 标注，注明默认不读。**原地归档，物理不移动**——冻结 ADR 正文不可改，正文里的相对链接无法重指，移动文件 = 制造永久断链（`session-model.md` 被五处冻结 ADR 正文引用 = 该约束的实证）；且本仓 agent 的默认上下文 = AGENTS.md 地图而非目录浏览（[operating-protocol](operating-protocol.md) §2 启动序列），地图标注即达成「退出默认检索」。内部链接完整性检查（§4）反向机械执行该纪律：任何文件移动制造断链即 CI 失败。
- **删除**：仅当内容明确无价值，且两个前提缺一不可——维护者批准 + 无入链（内部链接检查做全仓预检）。被冻结 ADR 引用的文档永远满足「有入链」，只可归档不可删。
- 归档标记 ↔ 地图标注的双向一致由机器检查（§4 第 4 项）。

## 3. freshness 元数据

- 范围：现役 `docs/design/*.md` 必带。豁免 = decisions（冻结即永恒）/ research（point-in-time，调研日期已充任）/ 归档件（归档即冻结）/ backlog（每会话自刷新，日期无义）。AGENTS.md 的 freshness 注先于本制度存在（头五行机器可查），原位不动。
- 格式：`Last reviewed: YYYY-MM`，住状态头引用块末行。
- 纪律：**改内容必 bump**——同一 change 触及正文即刷新该日期；只 bump 日期不算内容改动。
- 机器承诺边界（诚实条款，hve-core「规定规则 ≠ 执行规则」教训）：CI 只查在场与格式（§4 第 3 项）；「改动是否真的伴随 bump」由巡检用 git 历史对账（§5 第 1 项）。机器不谎报语义执行。

## 4. 机器膨胀信号

四项结构检查全部进 `just agent-check`（即 `just ci`）；检查语义与实现的 SSOT = `crates/xtask/src/agent_docs.rs` 模块文档。

1. **文档地图反向悬挂**：AGENTS.md 提及的 `docs/...` 路径必须存在（孤儿检查的反向——地图条目指向已删文档同为腐烂）。
2. **内部链接完整性**：`docs/**.md` 与 AGENTS.md 的相对 `.md` 链接的文件部分必须解析（锚点不查）。
3. **freshness 在场与格式**（§3 范围）。
4. **归档标记 ↔ 地图 `archived` 标注双向一致**（§2）。

**分层承诺（元纪律）**：机器只判结构（引用完整、日期在场、标注一致），不判语义——「能抓到文档被改名，抓不到它只剩空壳」。语义正确性归巡检（§5）与维护者抽检。任何「机器已保证文档仍正确」的读法都是过度承诺。

有意不做：相似度 / 冗余机器检测（误报会误伤导读式合理冗余，归 §5 人判）、引用计数（需埋点，§8）、TODO 滞留机器告警（先靠巡检）。

## 5. gardener 巡检

- 节奏：每任务收官轻巡检一次，发现随 backlog 收尾同一 commit 入库；深巡检 = 维护者明示触发。执行者 = agent。
- 轻巡检清单（五项）：
  1. **freshness 对账**：`git log -1 --format=%cs -- <file>` 与状态头 `Last reviewed` 比对，内容最后改动晚于复审月 = 悄悄过期信号；
  2. **冗余候选对**：通读 AGENTS.md 地图条目的职能描述，职能重叠者出示为合并 / 分流候选（判断位，机器不判）；
  3. **零维护文档列表**：长期无触碰的现役文档列出——复审触发，不是删除理由；
  4. `just agent-check` 全绿确认；
  5. **TODO / 待决滞留扫描**：长期滞留是 abandoned 文档的前兆。
- 产物去向：需行动者进 [backlog](../backlog.md) 遗留登记；无行动者 = 任务块状态行记一句。
- 人类决策点仅两处：**删除批准**（§2）与**压缩抽检**（§7）。

## 6. 入口闸门增补

既有闸门（三问过滤器、长度预算、孤儿检查）不动。增补两条：

- **新文档纪律**：新文档与地图条目同一 commit 入库（孤儿检查机器承接）；状态头声明类别 / 冻结面指针 / 寿命预期。
- **canonical 指定**：一个主题一个 canonical 文档；发现重复 → 合并，或弱者标「已吸收」转归档（§2）。**废弃标记优于沉默**：发现文档失效时标注归档 / 废弃永远优于沉默留置——加一句「已失效」也好过留着失效内容。

## 7. 压缩仪式

三原则（c2 wiki 实践 + 摘要幻觉实证，依据回溯 = RQ8 章）：

1. **保原文优先**：处置力度排序 删 > 移 > 并 > 改——生成式重写是最后手段，关键论断逐条核对；
2. **压缩者不自评**：agent 压缩，self-review 子代理判断 pass + 维护者抽检 diff；
3. **原文可恢复**：git 历史保底，大压缩不留额外副本。

流程：触发（巡检发现 / 任务收官 / 维护者指令）→ 压缩提案出示（删 / 移 / 并 / 改清单 + 理由）→ 维护者拍板 → **独立 change** 执行（压缩不混 feature，与 code-simplification 同纪律）→ 维护者抽检。已运行实例 = backlog 收官压单行；本节将其推广到全文档面。

## 8. 扩展位登记

- **staged diff 级 freshness 硬闸**（改文档必在同 diff bump 日期的 pre-commit 机器闸）：触发器 = 巡检反复抓到内容改动未 bump。
- **相似度 / 冗余机器检测**（n-gram / embedding 相似度）：触发器 = 巡检冗余候选对持续产出且人判成本失控。
- **引用计数**（context 装载埋点 → 零引用处置队列）：触发器 = 实现期 agent 读本规模化后。
- **TODO 滞留机器告警**：触发器 = 巡检第 5 项反复产出同一滞留条目。
