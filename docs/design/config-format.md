## 0. 术语锚点与既定地基

### 0.1 术语锚点（本文档新增；共享术语见 [luau-abi](luau-abi.md) §0 / [seam-capabilities](seam-capabilities.md) §0）

| 术语     | 含义                                                                                               |
| -------- | -------------------------------------------------------------------------------------------------- |
| 部署根   | 一个 Metis 部署的全部内容所住的目录 = 配置树文件所在目录（D29）                                    |
| 部署区   | 插件目录内部署者/agent 手写的文件（`config.yml`）：升级保留、分发排除（D36）                       |
| 运行期区 | 插件目录内运行期产物（`data/`）：升级保留、分发排除、gitignore（D29/D35）                          |
| 休眠件   | 树里有 entry 但 `enabled: false` 的插件：部署索引收录、不加载不对账不激活（D32；§A9.1 D24 原位）   |
| 未装配件 | `plugins/` 目录存在但树里无 entry 的插件（D34）                                                    |
| 残迹     | 卸载 keep 档后的插件目录：包内容已移除、`config.yml`/`data/` 保留；索引收录、运行期不吵（D48/D49） |
| 生效树   | base（`metis.yml`）∪ overlay 按 key 字段级合并的产物 = loader 实际消费的装配单（D38）              |
| 墓碑     | overlay 里的 `enabled: false` 行：卸载/禁用的显式留痕，审批 diff 可见、可逆（D38）                 |
| 重挂载   | 单插件热更新路径 = 卸载（§A4.5）+ 重启用（A9 判定重过）；与核心重启同一清理契约（ADR-0023）        |

## C1 部署根布局与配置树物理组织（2026-10-11 收官）

### C1.0 边界与前提

本题定**一切路径的锚点**：部署根选定方式、目录骨架、配置树文件面。不归本题：entry 树字段集（C2）、补丁分层与 diff 协调（C3/C4）、workspace 绑定语法（C5）、secrets store 内部形态（C6）、数据生命周期（C7）。

### C1.1 D29 部署根布局（2026-10-11 用户拍板）

- **部署根 = 配置树文件所在目录**：`--config path/to/metis.yml` 选定文件即选定根（ADR-0007 已立 `--config` 机制），`plugins/`、`lib/`、`.luaurc` 全部相对它解析。淘汰专门 `--deploy-root` 旗标（零新概念）。
- **目录骨架**：

```text
<部署根>/
  metis.yml                 # 配置树正本（人类手写层；惯例名，--config 可指他处）
  overlay.yml               # agent overlay 层（机器唯一可写的配置树文件，C3 详谈）
  .luaurc                   # @lib → ./lib/（见下）
  secrets.yml               # secrets store（豁免①；形态与纪律 = D46/D47）
  lib/                      # 部署级契约包（luau-abi §A8.2 三来源之二）
  journal/                  # journal 段文件 + blob 预留（豁免②；细节归任务 6）
  plugins/
    foo/
      manifest.yml          # 可选：无 = 零仪式插件（D35）
      config.yml            # 部署区：配置值稀疏覆盖（D36）
      main.luau             # 入口（manifest entry: 可改）
      lib/                  # 随包契约（既定）
      boxes/                # 盒制品（既定，wasm 里程碑）
      data/                 # 运行期区
        fs/                 # private scope 根（ctx.fs 挂载点）
        db.sqlite           # 私有 db（luau-abi §A3.9）
```

- **插件私有数据同居插件目录**：fs 私域根 = `data/fs/`、`db.sqlite` 与其平级——满足 luau-abi §A3.9「db 不在 fs 私域子树内」。淘汰集中数据根（`data/plugins/<name>/` 分居）：同居让「一个插件的全部」= 一个目录，卸载处置（C7）与备份/迁移粒度顺手。
- **global scope 豁免清单物理落点** = `secrets.yml` + `journal/` 两处（luau-abi §A3.7 两条豁免）；其余部署根 global 正常可达（维护/调试正道不变）。
- **版本管理纪律**：部署根可整体入库（部署即代码）；gitignore = `secrets.yml`、`journal/`、`plugins/*/data/`；sdk 脚手架生成 `.gitignore`。
- **`.luaurc` 布线落位**（兑现 luau-abi §A10.5 D28.5）：核心启动时检查部署根 `.luaurc`——不存在则自动生成（内容固定 = 含 `@lib` → `./lib/` alias，幂等）；存在则校验该 alias，不符 = 响亮报错指路 `metis sdk`。自动生成的理由：Creator 模式零仪式精神（文本即插件不该被工具链布线文件卡住）；`.luaurc` 是工具链布线不是配置层，不违反「机器只写 overlay」纪律。

### C1.2 D30 配置树单文件制（2026-10-11 用户拍板）

v1 = 单文件 `metis.yml` + overlay 一层，**不立 include 机制**。Cordis 的 Include（外部文件挂载 + 运行时写回）主要服务 bundle/profile 组合分发——bundle/profile 全套已判「包分发时代 machinery」（ADR-0004 / session-model §3），多来源问题已由 overlay 分层解决。登记扩展位，触发器 = 真实的文件拆分/分发需求（任务 9 时代复审）。

## C2 entry 树语法（2026-10-11 收官）

### C2.0 边界与前提

本题定**装配单的形状**：顶层形状、entry 字段集、休眠/未装配语义、插件形态单化、配置通道新形态、reload 原则。不归本题：补丁分层与写回纪律（C3）、diff 协调细则与 D37 机制展开（C4）。

### C2.1 D31 顶层形状 = `plugins` map，key 即身份（2026-10-11 用户拍板）

```yaml
# metis.yml —— 纯装配单
plugins:
  memory:        # null ≡ {} ≡ 全部缺省（启用、无字段）
  scheduler: {}
  llm-openai:
    enabled: false
```

- **map 形**，淘汰 Cordis 的 list + `id` 形（`cordis.yml` = entry 列表，每行带自动生成 id 供 keyed diff 定位）：① 身份 = 路径名且部署内唯一（§A2.1）——key 天然可作 diff 键，`id` 机制整个不需要；② key 即身份，「name 显式值必须等于目录名」的报错面按构造消失（无 name 字段可写错）；③ keyed diff 相等性平凡（ADR-0002 预言兑现）；④ 重复声明 = YAML map 重复键 = parser/校验层响亮。
- **归一规则**：entry 值 `null` ≡ `{}`（全部缺省）。校验器归一；机器写 overlay 用 `{}`（diff 可读性）。
- **加载顺序不靠声明序**（inject 拓扑驱动，ADR-0001）；受限 YAML 子集里 map 键序无语义。
- key 必须是合法目录名（禁 `/`、`.`/`..` 等）；校验进 loader/`sdk check` 同一实现（§A2.2 校验器单一实现、多面暴露哲学）。
- **已知牺牲**：Cordis `id` 的真实职能 = 同插件多实例（同一份代码、两份配置、各挂一份）；v1 答案 = 复制目录（`llm-openai-a/`/`llm-openai-b/`），代码重复与升级改 N 份的代价明记；复审触发器同 D32（任务 5 = 实例模型，子树落地）。

### C2.2 D32 entry 字段集 = `{ enabled }` 封闭集（2026-10-11 用户拍板）

| 字段      | 缺省   | 一句                                                                  |
| --------- | ------ | --------------------------------------------------------------------- |
| `enabled` | `true` | `false` = 休眠件：部署索引收录、不加载不对账不激活（兑现 §A9.4 登记） |

- **正面词 `enabled`（缺省启用）**，淘汰 Cordis 的 `disabled`（其 detached 行是准入失败产物，我们无此概念）；翻转 = 拓扑变更走 C4 diff。
- **未知字段 = 响亮报错**（与 manifest 政策 §A2.1 同款 typo 防线）。
- **config 不在 entry 树**：值住处 = 插件目录 `config.yml`（D36）。
- **不立并登记触发器**：`isolate` / 部署侧重命名（§A2.3 撞名本地解后两条）、`intercept`（Cordis：给某服务名下所有后代合并配置）、`group`/嵌套子树——四者都依赖**子树**概念，而子树 = 任务 5（实例模型，原 session 模型）议题；v1 撞名本地解 = 部署者二选一（`enabled` 足够表达），全程不改源码。触发器 = 首个真实撞名需求或任务 5 子树落地，同批复审。§A2.3 登记就此结案。
- （2026-10-11 结案注：C5 绑定字段不立——绑定机制整体不立 = D44；封闭集维持 `{ enabled }` 不变。）

### C2.3 D33 顶层节封闭集（2026-10-11 用户拍板）

顶层节 = 封闭集，**未知节 = 响亮报错**（typo 防线同 manifest）。v1 已知节：`plugins`、`core`（核心节——**已兑现 = §C8.1 D50**，2026-10-11）；绑定节——结案 = 不立（D44，2026-10-11）。配置树是部署者文件，演进 = 新节 additive + 老核心未知节响亮自然兼容，不立版本号机制。

### C2.4 D34 休眠件与未装配提醒面（2026-10-11 用户拍板）

- **休眠件**（树里有、`enabled: false`）：显式声明态、审批 diff 可见——**运行期不提醒**（不是 §A9.2 D25.1 那种「可能无期限的人为 Pending」）。禁用不丢配置：`config.yml` 住插件目录（D36），重新启用配置还在。
- **未装配件**（目录在、树里没有）：**运行期不吵**（配置树是唯一声明面，目录里多个目录不是核心的管辖事项）；`sdk check` 提示级列出未装配目录（写码期教具，不进运行期日志面）。
- **部署索引覆盖 = 目录扫描全量**：启动/安装扫描 `plugins/` 全量目录解析登记（休眠件与未装配件带状态标记，纯数据非判定——D24 原位）；依赖方 inject 未装配件 = 启用期响亮报错，与「查无」区分、指路「目录存在但树无 entry」；未装配件解析失败同休眠件政策（索引标记损坏 + host warn 一条，登记启用时响亮报错）。

### C2.5 D35 插件形态 = 目录单形态（2026-10-11 用户拍板）

- **淘汰单文件形态**（`plugins/foo.luau`）：一切插件 = 目录 `plugins/foo/`。ADR-0004 名字解析 4 条规则缩为 1 条（目录存在即可）；歧义格（`foo.luau` 与 `foo/` 共存）按构造消失；成长路径从「搬家」变「加 `manifest.yml`」，入口文件不动（§A1.3 零改写标准原样成立）。
- **manifest 保持可选**：无 manifest = 零仪式插件（原纯代码 niche 平移：无 config schema、无能力门资格、无 provide/inject——§A1.3 差异面原样，仅物理形态变）。Creator 模式产出 = mkdir + 写一个文件，仪式不增。
- **目录内三类文件规则**：包内容（manifest/代码/`lib/`/`boxes/`——升级替换、分发内容）/ 部署区（`config.yml`——升级保留、分发排除）/ 运行期区（`data/`——升级保留、分发排除、gitignore）。Creator 审批事务 diff 视野排除 `data/` 子树（运行期产物不进审批面）。
- **联动**：ADR-0004 局部 supersede（两形态格）——**已吸收 = [ADR-0027](../decisions/0027-config-format.md) 批次 #2**（2026-10-11）；§A1.3/§A2.1 修订注（本 change 已同步）。

### C2.6 D36 配置通道 = `config.yml` + 注入签名不变（2026-10-11 用户拍板）

- **值住处**：`plugins/<name>/config.yml`（部署区，目录顶层）。private scope 根是 `data/fs/`——**private scope 结构性够不到自己的 `config.yml`**；持 `global` 的插件读得到文件，但读到的只是**引用而非真值**（真值住豁免的 secrets store，§A3.7）——任何 scope 下旁路都拿不到秘密真值，校验与秘密解析只能过注入通道。
- **`setup(ctx, config, deps)` 签名不动**（§A3.3 原样）：核心启用期读 `config.yml` → 按 manifest schema 校验（缺 required/类型错/多给键 = 响亮失败，**插件代码一行未跑**——ADR-0006 前置原样保全）→ 秘密引用解析（§A2.5 机制原样，写处/解析源 = `config.yml`；写明文 = 校验拒绝；真值只进该插件 VM）→ 默认值合成（稀疏覆盖叠加 schema default）→ 冻结表注入。
- **变化面**：审批单位 = 插件目录 diff（`config.yml` 与代码同单位，ADR-0008 管线不动）；overlay 收缩为装配补丁层（装/卸/启用/绑定，不再管配置值）；`volatile` 词汇退役（其消费者 = 核心快路径机器，由 D37 替代——哪些键可热应用 = 作者文档 + handler 自行判断）。
- **两档分工**：声明式配置（`config.yml` + manifest schema：部署者可写、审批可见、sdk 可验）vs 完全自管（无 `config:` 节 = 核心零参与；运行期状态/偏好走 `data/fs` 或 db——判别两问之②，session-model §3）。db/私域自管配置不进审批面；文档引导部署决策走声明式通道。
- **休眠件的 `config.yml` 不校验**（D24：不使用的插件不检查）；required 缺失 = 启用期响亮失败，报错指路 `config.yml` 路径 + 键名。
- **无 `config:` 节 ≡ 空 schema**：`config.yml` 存在且有键 = 一切键按「多给键」响亮拒绝（ADR-0004 旧格「配值 → 响亮失败」精神平移；零仪式插件同规则）。
- **sdk 联动**：从 schema 生成 `config.yml` 模板（脚手架）；多插件配置全景聚合查看命令（登记 sdk 工具面）。
- **联动（supersede 批次——已吸收 = [ADR-0027](../decisions/0027-config-format.md) 批次 #1/#3/#4/#5**，2026-10-11）：ADR-0002（配置值 keyed diff / volatile 机器退役）、ADR-0006（值住处 + volatile 标注）、ADR-0007（overlay 收缩 + 机器写面扩张）、ADR-0008（模型配置写入面）、luau-abi §A2.0/§A2.1/§A2.5/§A2.7/§A3.3（措辞与解析点）——Status 行 interim 注与 doc 修订注本 change 已同步。

### C2.7 D37 reload 权利归插件（原则；机制归 C4）（2026-10-11 用户拍板）

- `config.yml` 变更（审批事务提交 / boot 检测 / 显式 reload 命令）→ **默认重挂载**（安全缺省）。
- 插件订阅配置更新通知（带新值推送）→ **live-apply 或否决后重挂载，权利在插件**（Cordis `internal/update` waterfall 否决先例：插件可参与配置更新决策）。
- 人直接编辑文件 = 下次 boot 生效；fs watch 实时感知 = 扩展位，v1 不立。纯轮转 secrets store（引用不变的值轮换）不产生 `config.yml` 变更——感知 = 显式 reload / boot（v1），fs watch 同扩展位。
- 机制细则（通知形状、否决通道、与 C4 diff 协调的衔接）——**已兑现 = D42**（2026-10-11）。

### C2.8 概念地基（2026-10-11 用户问答沉淀）

- **依赖为什么不住配置树**：依赖 = 作者意图，唯一住处 = manifest（`inject` 双列表 + `events` 双名单，§A2.5/§A8 已冻结）；配置树重复声明 = 重复税 + 漂移源（部署者声明的依赖与作者代码需求必然漂移）。**事件 listen ≠ 依赖**——listen 是弱耦合被动面（没人 publish 不是错误，观测类插件「听一切」是一等用法，§A10.3 D28.3 #5）；`inject` required 才是硬依赖（缺失 = 启用期 Pending/拒，§A9）。两条通道互补不替代。部署者在依赖面的正当角色 = 审批可见三栏（capabilities + inject + events listen，§A9.3 D26.2）+ 撞名时选实现（v1 = 二选一，D32）。
- **config 为什么住插件目录**：审批单位一体（agent 动配置 = 动插件，目录 diff = 代码 + 配置一体审批）；core agent-agnostic（配置值 = 插件的领域事务，核心不当保管人）；部署根自包含（一个目录 = 一个插件的全部）。平移而非退役的机制清单：schema SSOT（manifest）、校验前置（启用期、代码未跑）、秘密引用（写处平移）、默认值合成、类型生成（§A10.4 D19.3 原样）。
- **配置树 ≠ 配置值仓库**：配置树（装配单）只剩「装哪些、开不开」；插件运行期攒的状态/偏好从来就不进任何 YAML（判别两问之②，session-model §3）。（2026-10-11 修订注：「绑什么」随绑定机制不立撤除 = D44。）

## C3 补丁分层（2026-10-11 收官）

### C3.0 边界与前提

本题定**机器写面的补丁语义与落盘纪律**：overlay 形状与合并、写回时机与原子性、`config.yml` 双作者文件的注释保真。不归本题：diff 协调与 reload 机制（C4）；secrets store 内部形态（C6）。前提：overlay 收缩为装配补丁层（D36）；map 形 + `{ enabled }` 封闭集（D31/D32）；机器唯一可写的配置树文件 = `overlay.yml`（ADR-0007）。

### C3.1 D38 overlay 形状与合并语义（2026-10-11 用户拍板）

- **overlay.yml 与 metis.yml 同 schema**：顶层 `plugins` map、entry 字段集同一封闭集；同 parser 同校验器（§A2.2 校验器单一实现哲学）。机器写 overlay 用规范形（`{}` 不写 `null`，D31 归一规则既定）。
- **合并 = 按 key 字段级稀疏覆盖**：生效树 = base ∪ overlay；overlay 提到的 key 按字段赢，未提到的零意见。不立 Cordis 补丁词汇（`insert:` 行 / 按 id 定位整体替换）——那是 list 形 entry 树的税，map 形合并语义平凡（ADR-0002「keyed diff 相等性平凡」同根）。
- **卸载语义 = `enabled: false` 墓碑 + 审批事务处置目录**（包内容随事务移除；部署区 `config.yml` 与运行期区 `data/` 的处置粒度——**已兑现 = §C7.1 D48**：keep/purge 两档可选、缺省保留，2026-10-11），不立删除语法：① `null` 已被 D31 占用（≡ `{}`），兼作墓碑 = 同语法两义；② Cordis 先例正是「删除 = `disabled: true`」；③ 墓碑留痕审批 diff 可见、操作可逆（重新启用 = 机器删掉自己的 overlay 行，base 声明自然复活）；④ 目录处置后 + entry 休眠 = 一致静默（D34 休眠件政策原样覆盖）。残留写实：base 的 `foo:` 行与 overlay 的禁用行可能共存，人整理 metis.yml 时顺手清；指向查无目录的禁用行无害（合并产物 = 休眠件）。
- **机器对 overlay.yml 整文件所有权**（规范形重写自由），永不碰 metis.yml（ADR-0007「人类手写层永不被机器重写」不变）。
- **淘汰**：overlay 专用删除语法（两义冲突）；顶层 `removed:` 节（重开 D33 封闭集零收益）；整树替换形 overlay（机器须全知 base 才能写，破坏稀疏分层本意）。

### C3.2 D39 配置树文件写回纪律（2026-10-11 用户拍板）

- **机器写 overlay 的唯一时机 = 审批事务提交**（ADR-0008 管线：暂存 → 校验 → 审批门 → 原子提交）。v1 无自由运行期写回——Cordis 的 debounced write 服务运行时高频自写，我们的写源 = 离散事务，**debounce 不立**。
- **落盘 = tmp+rename 原子替换 + 串行写队列**（归实现期清单；Windows 句柄占用退避重试同归实现期）。
- **读-改-写在事务内**：overlay.yml 入库 git（D29）、人可手改——机器提交前重读现文件再施加补丁，不拿内存旧快照直接覆盖。
- **解析失败两分**：boot 时 metis.yml/overlay.yml 解析失败 = **响亮拒启动**、指路文件与行号（配置树 = 装配单，读不出不猜着跑）；运行期 v1 不重读树文件（无 fs watch，D37 扩展位），审批事务内 overlay 内容在暂存阶段已校验，提交后无解析失败窗口。Cordis「解析失败保留运行中树」的平移落点 = `config.yml` reload 路径（D42）。
- **淘汰**：运行期免校验热读树文件（与 D37「人改文件 = 下次 boot 生效」矛盾）；boot 解析失败降级为「忽略 overlay 继续跑」（静默丢 agent 装的件 = 装配被篡改却不响）。

### C3.3 D40 `config.yml` 机器写纪律（2026-10-11 用户拍板；ADR-0007 登记兑现）

- **问题定性**：D36 后 `config.yml` = 双作者文件（人手写带注释 + 机器经审批写），ADR-0007「注释保留问题架构性消解」的解法对它失效，纪律须重立。
- **最小 diff 纪律**：机器写 `config.yml` 时**未触碰区域字节级保留**（注释、格式、键序），只改动事务所涉键块；机器新写/重写的值走规范序列化。
- **可行性**：ADR-0007 受限子集（禁锚点/别名/自定义标签/多文档）使行块级补丁器可实现，不需要全保真 YAML round-trip parser。实现归实现期清单。
- **退档路径**：实现期补丁器质量不达标时退档 = **顶层键块整体替换**（该键块内注释丢失；审批 diff 事先显形损失，人审批时知情）。退档只影响注释保真度，不影响语义。
- sdk 模板脚手架（D36 登记）产物 = 规范形，同纪律。
- **淘汰**：机器整文件规范形重写（人的注释全灭、审批 diff 变噪音——ADR-0007 当年避开的问题原地回归）；`config.yml` 再分双层（D36 刚杀掉的 layering creep）。

## C4 diff 协调与 reload 机制（2026-10-11 收官）

### C4.0 边界与前提

本题定**变更的协调语义**：生效树 diff 的动作表、D37 reload 原则的机制展开（通知形状/否决通道）、部署 `lib/` 契约重对账时机。不归本题：绑定字段形状（C5）；插件目录内容变更的安装事务细则（实现期；ADR-0008 管线既定）。前提：ADR-0002 keyed diff 机器随 D36/D37 退役（配置值不再住配置树）；D37 原则（默认重挂载 + 插件否决通道）；§A8.5 D22.6 登记。

### C4.1 D41 装配 diff 协调语义（2026-10-11 用户拍板）

- **生效树 diff 的两个时机**：① boot = 全量加载，无 diff 概念；② 审批事务提交 = 新旧生效树 diff（生效树 = base ∪ overlay，D38）。map 形 diff = 按键三分，平凡。
- **逐 key 动作表**：

| 变更                                              | 动作                                       |
| ------------------------------------------------- | ------------------------------------------ |
| key 增                                            | 安装 + 启用流程（A9 判定细则原样）         |
| key 减（机器装的件撤 overlay 行且 base 无此 key） | 卸载流程（ADR-0018 S4 四段论，依赖者先卸） |
| `enabled` 翻转                                    | 卸载 / 启用                                |

（2026-10-11 修订注：原「绑定字段变更（C5 additive 位）→ 重启用」行撤除——绑定机制不立 = D44。）

（2026-10-11 修订注二：顶层节扩为 `{plugins, core}` 后（D50），diff 器对 `core` 节的动作 = host journal 换档即时生效，不涉插件重挂载——§C8.1。）

- **key 减幂等**：墓碑日后被清理（sdk 提示引导）时，key 减可作用于目录已不存在的件——卸载流程对此幂等（索引查无 → 仅摘树）。

- **失败隔离 = 逐 entry 非事务**（Cordis 先例平移：单行激活失败不影响兄弟行）：失败者落 Failed 显式状态 + `internal/plugin` 事件；依赖方走 D25.1 Pending + warn 既有机器。
- **同批多变更顺序**：先拆卸半相、后建设半相；建设半相内 inject 拓扑驱动（ADR-0001；声明序无语义，D31 既定）。
- **边界（树 diff 不管什么）**：`config.yml` 变更走 D42 通道；插件目录内容变更（代码/manifest/契约）= 安装事务协调（ADR-0008 管线既定：审批提交 → 重挂载该插件，热更新 = 重新启用 = §A8.3/D22.6 机器原样），本章不为其立新规。
- **淘汰**：装配变更事务化（整批全成或全滚——插件激活涉及真实效应，假回滚比显式 Failed 更撒谎；Cordis 明确选非事务，理由平移成立）。

### C4.2 D42 `on_config` 通知通道（D37 机制展开，2026-10-11 用户拍板）

- **触发点三处**（D37 既定）：审批事务提交 / 显式 reload 命令 / boot（boot = 新鲜加载，无 diff）。reload 命令操作面形态（CLI/控制接口）归实现期工具面。
- **管线先行**：新 `config.yml` 先过 D36 全管线（校验 → 秘密解析 → 默认值合成 → 冻结）。**校验失败 = 拒绝变更**：运行中实例持旧配置不动，响亮 surface（host 报错；journal 条目归任务 6）——「解析失败保留运行中树」在 config 面的平移（D39 登记）。文件保持坏状态等人修；下次 boot 该件启用响亮失败（D36 既定路径）。
- **结构相等 → no-op**（规范化比较复用 D18.3 机器）。
- **通道 = 入口 table 可选字段 `on_config`**（A1.1 封闭集的 additive 扩展——table 形态当年以「将来给入口挂新行为字段」的扩展性赢纯函数返回，本条兑现该扩展位；ABI 演进纪律 = additive + `abi_rev` bump，归 A10 机器）：

```luau
local function setup(ctx, config, deps)
    -- 照旧
end

-- 可选：配置更新通知；收到解析后冻结的全量新 config（与 setup 第二参同形）
-- current = 模块内自持的现行配置快照（setup 里赋值）
local function on_config(new_config)
    if new_config.refresh_interval ~= current.refresh_interval then
        return false  -- 吸收不了 → 核心重挂载我
    end
    current = new_config
    return true       -- live-apply 成交
end

return { setup = setup, on_config = on_config }
```

- **返回协议二元**：`true` = live-apply 成交（插件自负其责把新值用起来）；**其余一切 = 重挂载**——缺 handler / 返回非 `true` / 抛错（抛错附带日志，ADR-0014 fail-open 同族精神：handler 崩了不挡路，退安全缺省）。**不立 transform 返回**（config 以文件为真相，handler 改值 = 第三种 config 风味、文件与运行态漂移）；**不立永久否决**（文件已是真相，插件选择怎么吸收，不能拒绝现实）。
- **handler 可挂起**（fiber 邮箱回调同族，VM 时间盒原样）；全量推送 + 插件自持旧快照对比（淘汰 Cordis volatile 式按路径通知——与 setup 注入同形，零新概念）。
- **重挂载** = 卸载（§A4.5 优雅窗口 + 强杀预算）+ 重启用（新 VM、新 setup 拿新 config）；提供方重挂载 → 消费者 epoch 重启（ADR-0001/0018 既有机器）。live-apply 的价值正在此：自己吸收 = 消费者零感知。
- **秘密纪律按构造成立**：handler 住属主 VM，解析后真值定向投递属主——不存在广播事件携带真值的泄露面（§A2.5「真值只进该插件 VM」不破）。
- **竞态与排队**：handler 在飞或插件 Loading 中又来变更 → **合并取最新**（config 是状态不是事件流，跳过中间态合法）；在飞 handler 返回 `true` 只成交它所见的那一版，不抑制合并后最新版的再次投递（stale 成交不结案）。热更撞 Loading 中 setup = 惯性原则兑现（§A1.4 登记：进行中的加载跑完落定再响应）。重挂载后 setup 失败 → Failed 既有路径（D25.1 warn 机器接管可见性）。
- **观测面不立新事件**：`internal/plugin` 族 + journal（任务 6 登记）够用；审批 diff 本身 = 变更的第一观测面。
- **零仪式插件**（无 schema）按构造永不收到通知（config 恒空表，无变更源）。
- **淘汰**：① 开 `internal/update` 为 waterfall 广播事件（ADR-0016 💤 转正）——广播携带解析后真值 = 秘密泄露面；携带未解析引用 = 属主拿不到可用值、还须新立解析 API；否决权散给所有监听者，而「我的配置我做主」本质是属主专属权利。② ctx 新方法 `ctx.config.on_update(fn)`——生命周期钩子住处历来在入口 table/返回值轴（setup/dispose），不在 ctx 注册轴；table 字段让「此插件会 live-apply」跑代码前静态可见（analyze/审批友好）。

### C4.3 D43 部署 `lib/` 契约增删改的重对账时机（2026-10-11 用户拍板；§A8.5 D22.6 登记兑现）

- **触发点**：boot / 显式 reload（`lib/` 增删改 = 部署者动作，§A8.3 D22.6 既定框架）；fs watch 同 D37 扩展位。**agent 经审批提议部署根 `lib/` 变更 = 登记扩展位**——既定审批单位 = 插件目录 diff（ADR-0008），部署根契约提案的管道随契约分发时代定（任务 9 登记）。
- **语义 = D22.6 机器原样复用**：重扫 `lib/` → diff 契约命名空间 → 新增条目 additive 吸收；已有名字形状变更（规范化后不等）= 破坏 → 反向索引级联重启用全部引用方。与「插件随包契约热更新」同一台级联机器，不新造。
- **workhorse 写实 = boot 路径**：`lib/` 是部署级维护动作，通常本就伴随核心重启（ADR-0023 干净重启便宜）；热对账是同一机器的 bonus 用法。
- **失败隔离同 D41**：级联中某引用方重启用失败 = 该件 Failed，不拖兄弟。
- **淘汰**：仅 boot 生效、不立热对账通道（级联机器反正要为随包契约造，触发点加一个是零头；「契约变了要重启核心才知道」对部署者是不必要的钝）。

## C5 fs scope 收窄与 process 环境政策（2026-10-11 收官）

### C5.0 边界与前提

本题原题面 = workspace/命名根绑定机制 + env 收紧 + cwd 政策（§A3.7/§A3.10/§A3.13 登记；D33 绑定节登记位）。收官形态：**绑定机制整体不立**（fs scope 收窄两档），process 环境政策落 defaults。不归本题：secrets store（C6）。前提：seam §5.2 支配关系（已冻结）——process 继承核心进程 OS 全权，fs scope 分段/两条豁免/http 白名单均不经由它强制；§A2.5 secrets 走引用式不住 env。

### C5.1 D44 fs scope 收窄 = `{private, global}`（2026-10-11 用户拍板）

- **讨论回溯**：原题面 = workspace 绑定机制（住处与形状）。用户推翻前提——workspace 作用不明、似乎不需要；「插件需要某目录」应走参数/配置通道。
- **workspace 原设计意图写实**：fs 档间的**强制收窄中间层**（host 两段式解析强制，非约定）。与 process cwd/env 的本质区别：fs scope 是真实边界，process 参数从来不是边界（支配关系）。
- **拍板：scope 集收窄 = `{private, global}`，workspace 与绑定机制整体不立**。理由三条：
  1. **单数 workspace 无规范指称**——「这个部署的工作区是哪个目录」对通用部署无答案（core agent-agnostic 同族：「在工作目录上干活」是 agent 场景味，不是每个部署都有的概念）；真要多目录，单根版本来就半残。
  2. **功能需求已被覆盖**：「插件需要某目录」= 插件自己 `config.yml` 路径值 + global 能力（D36 通道，审批 diff 可见），零新机制。
  3. **中间层的诚实形态 = 命名根**（per-name 绑定）——保留为唯一中间层扩展位（§A3.7 既定，词汇 + 绑定机制同批走 ABI rev）；不先立语义牵强的单数半成品。
- **代价写实**：fs 审批两档化（private/global）；碰用户文件的插件一律 global 最高档（要么信要么不信）；无强制目录收窄，偏执部署走 OS 级沙箱——与 process 外墙同一答案，seam §5.2「外墙归部署组成（任务 4 登记）」就此结案（核心不立机制，归部署指南文档面）。
- **插件无需知道配置目录在哪**：维护/调试走 global 可达部署根（§A3.7 既定）不变。
- **连带**（supersede 批次——**已吸收 = [ADR-0027](../decisions/0027-config-format.md) 批次 #6/#7/#8/#9**，2026-10-11：**首次触及冻结中的 ABI（ADR-0025/0026）**，实现未落地，演进纪律破坏式通道）：luau-abi §0 术语锚点 scope 行；§A3.7 三 scope 表 → 两 scope（含表格本体与 scope↔命名空间对应规则行）；§A3.2 ctx 命名空间去 `workspace`；§A2.5 fs scope map 词汇；§A10.3 D28.3 #2 规则收窄；§A9.4「绑定机制归任务 4 + 未绑定根调用期响亮与判据 2 边界写清」结案 = 不立（moot）；§A3.10 实现节奏行类比修订；seam §5.2 fs 行两 scope 化 + §5.3/§6.1「三 scope」复述处。本文档自家：D32 additive 位备注、D33 绑定节登记位、D41「绑定字段变更」动作行、C1.3/C2.8/C2.9/C3.4 的绑定相关登记——结案不立（修订注本 change 同步）。

### C5.2 D45 process 环境政策（env 收紧结案 + cwd 政策；2026-10-11 用户拍板）

- **env = 继承核心 env + 覆盖，不立收紧层**（§A3.10「env 收紧政策归任务 4」结案 = 不立）：
  - 收紧挡不住同 OS 用户 `/proc/<pid>/environ` 读取——立了是假边界（严格制厌恶的模糊处理）；
  - secrets 按 §A2.5 不住 env（泄露面结构上小，既定）；
  - process 审批权重已按 ⊇ `global: write` + 任意域 http 展示（seam §5.2 既定）。
  - 配套：审批/Creator 文档写明「子进程继承核心环境变量、secrets 不住 env」纪律。触发器 = 多租户/托管形态（core 高权、插件降权）到来时重议，与 OS 级沙箱外墙同批。
  - 淘汰：部署级 deny 清单（blocklist 永恒不完整 + 可绕过 = 假安全感）；默认清空 + 允许清单（无 PATH/HOME，ergonomics 死亡）。
- **cwd 政策**：缺省 = **用户家目录**（落选缺省 = 私域：子进程是任意代码、不受私域边界约束，拿私域当 cwd 只给出假 confinement 暗示；家目录 = 用户世界直觉缺省）；家目录不可解析（HOME/USERPROFILE 未设、服务账户）= **响亮报错**指路显式传 `cwd`（严格制：不猜、不静默退档）；显式 cwd = 任意绝对路径（非边界写实：cwd 不构成 confinement，与支配关系同源）；相对 cwd → 相对家目录解析（与缺省同一解析基，零特例）；cwd 不存在 = spawn 自然失败（`process.spawn_failed`），不预检。（修订 §A3.10 原「cwd 缺省 = 绑定的 workspace 根，未绑 = 私域」——workspace 收窄随 D44。）
- **插件域默认工作目录**（如 shell 插件的项目目录）= 插件自己 `config.yml` 的事（D36 通道），核心零参与；登记 Creator/插件作者文档引导。

## C6 secrets store 内部形态与纪律（2026-10-11 收官）

### C6.0 边界与前提

本题定 secrets store 的内部形态与运行纪律（§A2.5「store 细节归任务 4」兑现；C1.3 登记）。既定地基（只承接不重审）：引用式秘密机制（§A2.5——schema 标 `secret: true` → 只许写 `{ secret: "name" }` 引用、写明文 = 校验响亮拒绝、真值只进属主 VM、人类手写层机器永不写）；物理落点 = 部署根 `secrets.yml`（D29）；两条豁免 carve-out（§A3.7：一切 fs scope 读写同禁）；轮转感知 = 显式 reload / boot（D37）。

### C6.1 D46 `secrets.yml` 内部形态（2026-10-11 用户拍板）

```yaml
# secrets.yml —— 人类手写层；机器永不写；gitignore（D29）
openai-prod: sk-...
backup-ssh-key: |
  -----BEGIN OPENSSH PRIVATE KEY-----   # ← pr-guard:allow（文档示例占位，非真实秘密；marker = 仓库 secret-scan 的示例豁免约定）
  ...
```

- **形状 = 扁平 map `name: value`，值仅限字符串**；多行字符串 = PEM 类钥匙正例。结构化秘密（keypair 等）= 拆多个名字；嵌套 map/数组值 = 响亮拒绝（受限子集校验兜底，ADR-0007）。
- **名字 = 部署级共享命名空间**：`{ secret: "openai-prod" }` 引用全局解析；无 per-plugin 隔离（名字是部署者词汇，撞名 = 同值，无害）。
- **文件缺席 ≡ 空 store**；引用查无 = 启用期响亮失败（§A2.5 既定路径原样）。
- **淘汰静态加密 at rest**：主密钥住处无解（住 env → `/proc` 同源泄露；住文件 → 鸡生蛋）；v1 = 明文 + 权限锁 + gitignore（§A2.5 承诺原样兑现）；触发器 = 托管/合规需求，届时外挂 KMS/age 类形态再审。

### C6.2 D47 secrets 纪律（权限档 + 加载/轮转感知；2026-10-11 用户拍板）

- **权限锁落档**：boot 检查 `secrets.yml` 权限；POSIX 下 group/other 可读 → **host warn 一条 + 继续，不拒启动**（容器/orchestrator 挂载的 secret 常是 0644 root-owned，拒启动太脆；warn = D25.1 人读面精神）；sdk 脚手架生成时 chmod 0600；Windows ACL best-effort 归实现期。
- **加载 = boot 一次性读入内存**（core 自持 map）；解析点 = 启用期 config 管线（D36 既定）。
- **轮转感知 = 显式 reload / boot**（D37 既定，本条落位）：reload 重读 `secrets.yml` → 重跑受影响插件 config 管线 → 结构不等 → D42 通道（`on_config` / 重挂载）。引用不变值轮换对运行中插件零感知直到 reload——写实。
- **机器永不写**（ADR-0007 人类手写层延伸，§A2.5 既定）；agent 无提议秘密变更的通道（审批单位 = 插件目录 diff），不立。
- **解析失败两分**：boot 读到坏文件（YAML 解析失败 / 受限子集校验拒绝）= **响亮拒启动**、指路文件与行号（D39 同族：读不出不猜着跑——静默置空会让一切引用炸成「查无」，误导排查）；显式 reload 读到坏文件 = **拒绝本次 reload、运行中实例持旧 map 不动** + 响亮 surface（D42「校验失败 = 拒绝变更」在 secrets 面的平移）。
- **联动**：秘密值按身份注册脱敏管线 = 任务 6（§A2.5 既定）；journal 加密密钥形态/住处 = 任务 6（D7.2 登记，住处候选 = secrets store 同族机制，届时定）。

## C7 数据生命周期：卸载处置与残迹政策（2026-10-11 收官）

### C7.0 边界与前提

本题定**卸载后插件目录剩什么**：`config.yml` 与 `data/` 的处置粒度（D38 不预决项兑现；§A3.9「db 卸载保留归任务 4」兑现）与保留形态的索引交互（C3.4 登记）。不归本题：升级处置（D35 已定保留部署区/运行期区）；数据备份/迁移/配额（无登记需求，不立）；journal 数据生命周期（任务 6）。前提：目录单形态（D35）；私有数据同居插件目录（D29）；卸载语义 = 墓碑 + 审批事务处置目录（D38）；部署索引 = 目录扫描全量（D34）。

### C7.1 D48 卸载处置粒度 = 两档可选、缺省保留（2026-10-11 用户拍板）

- **卸载两档**：
  - **keep（缺省）**：包内容移除；`config.yml` + `data/` 保留 = 残迹目录（D49）。
  - **purge**：目录整体移除（含 `config.yml` + `data/`）。
- **档位选择归部署者**（卸载动作发起时选定；sdk 旗标 / 审批面展示位）。**agent 提议卸载固定 keep 档**——删数据不进 agent 提议面（与 D47「agent 无提议秘密变更通道」同族：破坏性动作的提议权不交机器）；要全删 = 部署者自己动手。
- **残迹的事后 purge** = `sdk purge <name>` / 手工 `rm -rf`（部署者专属；残迹经 D49 索引可见，不会遗忘）。
- **缺省保留的理由**：`db.sqlite` 装着持久意图（schedule 插件的提醒记录、memory 的记忆库——§A2.7 原则 1「意图数据持真相」），`config.yml` 是部署者手写/审批产物；「卸载」的语义 = 不再参与运行，不是历史蒸发——**删数据是显式动作，不是移除代码的副作用**。与 D35 升级保留同向：禁用（休眠）→ 卸载（移除代码）→ purge（删数据）逐级加强。
- **淘汰**：全删唯一档（误卸 = 持久意图永久丢失）；「留 config 删 data」分界（db 里的持久意图恰恰不可再生，分界不一致反难记）。

### C7.2 D49 残迹目录的索引与扫描交互（2026-10-11 用户拍板）

- **残迹定义**：目录内无 manifest 且无入口文件（无包内容），但有 `config.yml` 或 `data/` 残留。部署索引标记「残迹」状态——不立此状态则按 D34 政策误归「解析失败」（索引标损坏 + host warn 一条，每 boot 白吵）。
- **运行期不吵**（同 D34 未装配件政策）；`sdk check` 提示级列出残迹 + purge 指路。
- **inject 面无特殊 casing**：残迹无 manifest 不提供任何 provides；依赖方走「查无」同族响亮（D25.1 行四原样）；实现期可在报错措辞层加残迹指路（「该 key 曾由残迹目录提供」），不立机制。
- **同名重装 = 复活**：包内容落回残迹目录，`config.yml` + `data/` 自然接上（name = 身份，D31）；同名新插件继承旧数据 = sdk/审批面提示「目录含前任残迹」（展示位，不立核心机制）。新插件 schema 与残留 `config.yml` 不符 = 启用期校验响亮（D36 管线原样）；db schema 演化 = 插件自家事（§A3.9 私有 db 既定）。
- **空目录**（无包内容、无 config、无 data）：索引不收录（纯噪音源）。
- **残迹的 `config.yml` 不校验**（无 schema 可校，同 D36 休眠件政策）。

## C8 核心节（2026-10-11 收官）

### C8.0 边界与前提

本题定**核心节形状**（D33 登记位兑现：audit 降档键住处）与**一等 cron 复审结案**（§A2.7 / seam §5.5 登记）。不归本题：journal 记录格式与降档语义本体（§A6.7 D7.1 已定，正式设计归任务 6）；schedule 插件立项（插件层议题，默认插件集批次）。前提：顶层节封闭集（D33）；overlay 与 metis.yml 同 schema + 按 key 稀疏合并（D38）；audit 族 v1 默认降档、开关面 = 配置键（§A6.7 D7.1）。

### C8.1 D50 核心节 = `core:`，audit 降档键形状（2026-10-11 用户拍板）

```yaml
# metis.yml
core:
  audit:
    fs: off        # off | summary | full，缺省 off
    sql: summary
```

- **节名 `core:`**；顶层节封闭集 = `{plugins, core}`（未知节响亮报错不变，D33 机制原位）。
- **键 = audit 族名，封闭集校验**（typo 防线同 manifest）：v1 可调族 = `fs` / `sql`（fs_read/fs_write、sql_call/sql_result per-call 条目，§A6.7 D7.1）。其余族不在可调面：http/timer/生命周期/code_ref 族 = ★ replay 必需族全录写死；`process_spawn`/`process_exit` 元数据不降档写死（D7.1「藏不住」护栏）。新族 = 新键 additive（D33 演进机制原位）。
- **值 = 三档枚举**：`off`（缺省——D7.1 张力注记「fs/sql 面默认失明」原位）/ `summary`（聚合摘要：「本消息处理窗口 fs_read ×12」）/ `full`（调试窗口期全录）。未知值 = 响亮报错。
- **overlay 可补丁 `core:` 节**（D38「同 schema + 按 key 字段级稀疏合并」不豁免）：agent 提议开审计窗 = overlay diff 审批可见；反向提议**关** audit 同理审批兜底——审批机器的意义正在于此。
- **生效路径**：audit 键 = host journal append 侧政策，不涉插件——生效树 diff 对 `core` 节 = host 换档即时生效（下次写入用新档），无重挂载（D41 修订注二已同步）。

### C8.2 D51 一等 cron 复审：结案 = 维持不立（2026-10-11 用户拍板）

- **复审结论 = 维持 §A2.7**（v1 = config 键约定，不立 manifest 一等 `schedule` 字段）：原始淘汰理由不随配置格式变化动摇——一等字段 = 第三台调度机器（与梯度一易失 timer、梯度二持久调度插件重叠），且「多久跑一次」是部署政策不该由作者写死进包。config 键约定在 `config.yml` 时代完整保留（schema 校验/默认值/审批 diff 全在原位，D36）；审计牙原样（`timer_scheduled` 条目 + analyze #13 硬编码间隔告警）。
- **梯度二持久调度 = 插件层议题**：schedule 插件立项归默认插件集批次（四件套原则已备，§A2.7）；持久意图载体 = sqlite，与 manifest 字段无关。
- **触发器**：schedule 插件立项时出现 config 键表达不了的声明式调度需求 → 走 ABI rev additive 通道（A10 既定）重议。
